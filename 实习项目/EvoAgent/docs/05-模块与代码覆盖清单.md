# EvoAgent 模块与代码覆盖审计

审计日期：2026-08-27

## 审计口径

本清单按“代码文件 / 资产”盘点，不按功能名称盘点。覆盖等级：

| 状态 | 含义 |
|---|---|
| A（已覆盖） | 文件的核心职责、主要生命周期和关键接口已在现有文档中说明 |
| B（部分覆盖） | 文件或其主要概念被提到，但仍有重要 API、边界或未实现的现状没有展开 |
| C（未覆盖） | 文件在审计前的五篇架构文档中没有出现，或仅有一句概括 |

结论：**现有文档没有覆盖所有模块和代码**。它更像一份“产品架构与运行链路说明”，而不是“EvoAgent 代码手册”。

## 总体判断

产品主链路覆盖最好：

- API、Service、Harness、Runtime、Agentic Core、Context、Memory、Gate、Reviewer、Queue；
- 一次请求的状态转移；
- 任务、轨迹、checkpoint、记忆、版本与恢复的主要入口。

主要缺口集中在四个方向：

1. **评测与离线实验体系**：受控 benchmark、真实 PR 评测、Critic 消融、Prompt 离线证明；
2. **数据契约与基础模块**：`models.py`、`modes.py`、`telemetry.py` 没有被作为独立模块解释；
3. **运行脚本与测试资产**：四个 `scripts/*.py` 和 17 个 `tests/*.py` 没有纳入文档；
4. **资产目录与外部集成细节**：9 个 Agent Skill 的内容、完整 API 路由、GitHub App、PostgreSQL 差异没有逐一说明。

### 实际测试冒烟

在当前环境 `Python 3.10.11` 下运行：

```text
python3 -m unittest discover -s tests -v
```

结果：**63 项测试，62 项通过，1 项失败**。

失败项：

`test_safe_fixer_changes_only_supported_rules`

失败原因是测试期待 `password = os.environ["PASSWORD"]`，但 `SafeFixer` 通过 `ast.unparse` 输出的是单引号 `password = os.environ['PASSWORD']`。两类引号语义等价，测试断言对字符串格式化过于严格，属于测试脆弱性，不是产品主链路失败。

补充事实：

- `SafeFixer` 被 `service.py` 导入，但当前产品服务实际使用的是 `VerifiedPatchFixer` 或 `SuggestionOnlyFixer`；
- `SafeFixer` 目前主要出现在 `tests/test_advanced.py`，属于“已有实现但产品未接入/剩余代码”；
- `README.md` 声明 Python 3.11，当前审查环境是 Python 3.10.11，版本差异可能是该测试失败的环境因素之一。
