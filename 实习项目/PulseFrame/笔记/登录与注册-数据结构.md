# MySQL 表

流程说明见 [登录与注册](登录与注册.md)。本文件定义用户名密码注册、QQ 登录、刷新会话及封禁所需的数据结构。

1. 通用约定
```text
使用 MySQL 8.0.16 及以上版本、InnoDB，外键与 CHECK 约束必须生效。
userId 对应 users.id，使用服务端生成的规范小写 UUIDv4。
UUID、用户名、哈希和第三方身份字段使用 ASCII 字符集与 ascii_bin 比较规则。
其他文本使用 utf8mb4；所有 DATETIME(3) 均由应用按 UTC 写入。
下表未注明“可空”的字段均为 NOT NULL；created_at、updated_at 由应用维护。
外键统一引用 users.id，采用 ON DELETE RESTRICT、ON UPDATE RESTRICT。
```

1.1 users：用户主表

| 字段 | 类型 | 默认值或约束 | 用途 |
| --- | --- | --- | --- |
| id | CHAR(36) | 主键，应用生成 UUIDv4 | 所有登录方式共用的用户标识 |
| status | VARCHAR(16) | 默认 active，CHECK 限定 active、disabled | 账号正常或禁用状态 |
| auth_version | BIGINT UNSIGNED | 默认1，CHECK 大于等于1 | 封禁或撤销全部登录时递增 |
| created_at | DATETIME(3) | 创建时的 UTC 时间 | 用户创建时间 |
| updated_at | DATETIME(3) | 最近修改时的 UTC 时间 | 状态或版本修改时间 |

```text
登录、刷新按主键读取 status、auth_version。
恢复账号只将 status 改为 active，不减少 auth_version。
当前不在此表保存密码、Refresh Token 或“是否在线”字段。
```

1.2 password_credentials：用户名密码凭据表

| 字段 | 类型 | 默认值或约束 | 用途 |
| --- | --- | --- | --- |
| user_id | CHAR(36) | 主键，同时为 users.id 的外键 | 一个用户最多一组本地密码凭据 |
| username | VARCHAR(24) | 唯一索引 uk_password_username | 统一小写的登录名 |
| password_hash | VARCHAR(255) | 无默认值，ASCII | Argon2id 的完整 PHC 编码结果 |
| created_at | DATETIME(3) | 创建时的 UTC 时间 | 凭据创建时间 |
| updated_at | DATETIME(3) | 最近修改时的 UTC 时间 | 凭据修改时间 |

```text
username 只接受3至24个 ASCII 字母、数字或下划线，写入和查询前统一小写。
password_hash 已包含算法、版本、参数、随机盐与哈希，不另建明文密码或盐字段。
密码输入为12至128个 Unicode 字符、UTF-8 最多512字节，不改写或截断。
用户与密码凭据在同一事务创建；用户名并发冲突由唯一索引判断。
QQ 创建的用户可以没有本表记录，不为其生成默认密码。
```

1.3 external_identities：第三方身份关联表

| 字段 | 类型 | 默认值或约束 | 用途 |
| --- | --- | --- | --- |
| provider | VARCHAR(16) | 当前取 qq | 第三方平台名称 |
| app_id | VARCHAR(32) | QQ 应用配置中的 appId | 区分不同应用下的身份 |
| openid | VARCHAR(128) | 由服务端向 QQ 验证取得 | 当前应用内的第三方用户标识 |
| user_id | CHAR(36) | users.id 的外键 | 对应本地用户 |
| created_at | DATETIME(3) | 创建时的 UTC 时间 | 首次关联时间 |

```text
联合主键：(provider, app_id, openid)，保证同一第三方身份只能关联一个用户。
普通索引：idx_external_user(user_id)，用于查询用户关联的第三方身份。
新建用户和关联记录使用同一事务；唯一约束冲突时回滚，再查询已有记录。
已有账号绑定 QQ 必须完成本地近期认证和 QQ 授权，不能按昵称或邮箱自动合并。
QQ access_token、授权码及 appSecret 不保存在本表；当前仅将 QQ 用于登录。
```

# Redis key-value

1. 通用约定
```text
key 中的 {...} 表示需要替换的业务标识。
Hash 的数字和时间字段以十进制字符串保存，时间统一为 Unix 秒数。
限流 ZSET 的 score 使用 Unix 毫秒数。
Refresh Token 为48字节安全随机数的无填充 base64url 编码。
tokenDigest = SHA-256(原始 Refresh Token)，编码为64位小写十六进制。
随机高熵令牌使用 SHA-256 摘要；用户密码仍使用 Argon2id。

会话绝对期限 = 首次登录时间 + 7天，使用 EXPIREAT 设置。
轮换不会延长会话、新旧令牌映射的期限；Access Token 不存 Redis。
当前采用单主 Redis，跨 key 的会话操作使用 Lua 原子执行。
```

1.1 session:{sessionId}：刷新会话

类型：Hash。登录时创建，轮换时更新当前令牌摘要；退出、重放或刷新发现账号禁用、版本失效时删除，其余会话按绝对期限自动到期。

| value 字段 | 内容 | 作用 |
| --- | --- | --- |
| userId | users.id | 会话所属用户 |
| authVersion | 创建会话时的 users.auth_version | 刷新时与 MySQL 当前版本比较 |
| currentTokenDigest | 当前 Refresh Token 的 SHA-256 摘要 | 保证同一会话只有一个当前刷新令牌 |
| deviceId | 客户端提供的设备标识，可为空字符串 | 会话展示参考，不用于证明设备身份 |
| ip | 创建会话时可信来源的客户端地址 | 风险判断参考 |
| userAgent | 创建会话时的 User-Agent，可为空字符串 | 会话展示与风险判断参考 |
| createdAt | 首次登录的 Unix 秒数 | 会话起点 |
| absoluteExpiresAt | createdAt + 604800 | 会话不可延长的到期时间 |

```text
sessionId 使用安全随机的128位标识，不由 deviceId 派生。
IP 只从连接信息或配置可信代理提供的头部取得，不能直接信任任意转发头。
登录原子创建会话；若随机标识已存在，不覆盖已有会话。
EXPIREAT session:{sessionId} absoluteExpiresAt
刷新脚本检查会话存在与当前摘要，再更新 currentTokenDigest。
已删除的会话不能由刷新脚本重新创建。
```

1.2 refresh:{tokenDigest}：刷新令牌映射

类型：Hash。原始 Refresh Token 仅通过 HttpOnly Cookie 交给浏览器。

| value 字段 | 内容 | 作用 |
| --- | --- | --- |
| sessionId | 对应刷新会话标识 | 定位 session:{sessionId} |
| state | current 或 used | 当前有效令牌，或已被轮换使用的旧令牌 |

```text
创建时 state = current，EXPIREAT 设置为会话的 absoluteExpiresAt。
轮换时原子完成：旧映射标记 used、新映射创建、会话当前摘要更新。
旧映射保留至原绝对期限，以识别旧令牌重用并撤销所属会话。
映射存在但会话不存在时，不能刷新。
退出后映射可自然到期，无需扫描并删除该会话的所有历史摘要。
```

1.3 user:{userId}:sessions：用户会话索引

类型：Set。value 为该用户的 sessionId 集合。

```text
SADD user:{userId}:sessions {sessionId}

创建会话时与会话、令牌映射一同写入。
索引到期时间取现有到期时间与新会话 absoluteExpiresAt 的较大值。
轮换沿用 sessionId，不把原始令牌或令牌摘要放入该集合。
退出或旧令牌重用时，删除会话并 SREM 对应 sessionId。
创建、刷新时，移除集合内已无对应 session 的成员。
集合可能暂时包含自然到期的 sessionId，不能仅凭集合成员判断已登录。

封禁或全部退出通过 MySQL 中的 status、auth_version 阻止旧会话刷新。
无需枚举索引批量删除会话；旧会话及令牌映射按原绝对期限到期。
刷新发现账号禁用或版本失效时，删除该会话并 SREM 对应成员。
```

1.4 oauth:qq:state:{stateDigest}：QQ 授权的一次性上下文

类型：Hash。state 与浏览器绑定凭据分别由32字节安全随机数生成；stateDigest 为 state 的 SHA-256 十六进制摘要。

| value 字段 | 内容 | 作用 |
| --- | --- | --- |
| browserBindingDigest | 浏览器绑定凭据的 SHA-256 摘要 | 防止其他浏览器拿同一 state 完成登录 |
| appId | 服务端配置的 QQ 应用标识 | 确定本次授权所属应用 |
| redirectUri | 已登记的 HTTPS 回调地址 | 换取凭据时使用的固定回调地址 |
| returnPath | 服务端允许的同源前端路径 | 授权完成后的跳转位置 |
| purpose | login 或 bind | 区分登录与绑定账号 |
| targetUserId | 绑定时为当前用户；登录时不写该字段 | 确定绑定目标，不能由回调参数替换 |
| targetAuthVersion | 绑定前读取的账号版本；登录时不写 | 防止账号被撤销登录后继续完成绑定 |
| reauthenticatedAt | 绑定前重新认证的 Unix 秒数；登录时不写 | 记录本次绑定的近期认证 |
| expiresAt | 创建时间 + 300 | 一次性授权期限 |

```text
EXPIREAT oauth:qq:state:{stateDigest} expiresAt
绑定前必须重新认证；绑定回调检查账号正常、版本一致且认证在5分钟内。
回调用 Lua 校验 state、浏览器绑定摘要和期限，匹配后才删除并消费。
失败、过期或已消费的 state 不能继续换取登录凭据。

浏览器绑定凭据通过独立 Cookie 下发：
qqOAuthBinding=...; Path=/api/oauth/qq; HttpOnly; Secure; SameSite=Lax; Max-Age=300
授权入口与回调位于 /api/oauth/qq/ 下，成功消费后按相同属性清除 Cookie。
不保存 QQ 授权码、QQ access_token 或 appSecret。
```

1.5 rate:*：登录与注册频率计数

类型：ZSET。每个成员为服务端生成的唯一请求标识，score 为允许进入验证或注册处理时的 Unix 毫秒数。

| key | 计数维度 | 窗口及额度配置 |
| --- | --- | --- |
| rate:login:account:{usernameDigest} | 统一小写后的用户名的 SHA-256 摘要 | LOGIN_ACCOUNT_WINDOW、LOGIN_ACCOUNT_LIMIT |
| rate:login:ip:{ipDigest} | 可信来源且规范化的 IP 的 SHA-256 摘要 | LOGIN_IP_WINDOW、LOGIN_IP_LIMIT |
| rate:register:ip:{ipDigest} | 可信来源且规范化的 IP 的 SHA-256 摘要 | REGISTER_IP_WINDOW、REGISTER_IP_LIMIT |

```text
窗口配置单位为毫秒，额度为窗口内允许进入处理的请求数，启动时校验为正值。
Lua 清理窗口外成员，检查本次相关维度；全部通过才向相关集合增加请求。
登录密码错误、用户名注册冲突等处理失败不退还已使用的额度。
触发限制返回429，被拒绝的请求不继续新增成员，避免集合无限增长。
每次新增成员后，PEXPIRE 设置为对应窗口长度；自然到期后自动释放。
Redis 故障返回503，不能跳过频率检查继续执行登录或注册。
具体窗口和额度按部署流量配置，本文件不预设未经验证的生产数值。
```

2. 各流程读写关系

| 流程 | MySQL | Redis |
| --- | --- | --- |
| 注册 | 同一事务写 users、password_credentials | 检查注册频率计数 |
| 密码登录 | 查 password_credentials、users | 检查登录频率，创建会话、令牌映射与用户索引 |
| QQ 登录或绑定 | 查写 external_identities、users；绑定时检查目标版本 | 创建并消费 QQ state；登录成功后创建会话 |
| 业务请求鉴权 | 不因 JWT 验证查库；资源权限按业务判断 | 不因 JWT 验证查询 |
| 刷新 | 查 users.status、auth_version | 原子轮换令牌映射与当前摘要 |
| 当前会话退出 | 无 | 原子删除会话及索引成员 |
| 封禁或全部退出 | 封禁时更新 status 并递增 auth_version；全部退出仅递增版本 | 无需批量删除，旧会话无法续期并按 TTL 到期 |
| 恢复账号 | 更新 users.status，保留递增后的版本 | 旧会话不能恢复使用 |
