# 03 阅读代码

日期：2026-10-05

当前代码只保留工程基座。建议沿启动流程阅读，先理解一个 Go HTTP 服务怎样完成配置、路由、日志和优雅退出。

## 阅读顺序

1. backend/cmd/pulseframe-api/main.go：进程入口和依赖装配。
2. backend/internal/config/config.go：环境变量读取与校验。
3. backend/internal/server/router.go：基础中间件和健康接口注册。
4. backend/internal/server/server.go：监听、就绪状态与优雅退出。
5. backend/internal/middleware/：请求标识、访问日志和异常恢复。
6. backend/internal/response/error.go：统一错误结构。
7. backend/test/：从公开 API 验证以上行为。

## 主调用流程

~~~mermaid
flowchart TD
    A[main 调用 run] --> B[config.Load]
    B --> C[signal.NotifyContext]
    C --> D[logging.New 和 gin.SetMode]

    F --> G[server.New]

    H --> I[收到取消信号]
    I --> J[撤销就绪状态并优雅退出]
~~~

## main 和 run

main 把 context.Background() 和 os.LookupEnv 交给 run。入口自身不能向调用方返回错误，因此 run 失败时记录错误并以非零状态结束进程。

run 负责装配，不处理具体 HTTP 请求。它按顺序创建配置、生命周期上下文、日志器、健康状态、路由和 HTTP Server。每个步骤失败后立即返回，避免服务以部分初始化状态开始监听。

## 配置

config.Load 的输入是环境变量查询函数。把读取函数作为参数传入后，测试可以提供独立配置源，无需修改进程环境。

loadHTTP 负责 HTTP 参数；validateAddress 检查监听地址；parsePositiveDuration 确保各项时长可以解析且大于零。

## 路由和中间件

server.NewRouter 使用 gin.New() 创建路由器，并按以下顺序注册中间件：

1. 请求标识：接收合法上游标识或创建新标识。
2. 访问日志：记录方法、路径、状态码、耗时和请求标识。
3. 异常恢复：捕获 Handler 中的 panic，记录原因并返回统一错误。

随后注册 /livez、/readyz、404 和 405 处理函数。

## HTTP Server

server.New 只创建对象并校验参数。Server.Run 才开始监听端口。监听成功后，服务发布就绪状态；上下文取消后，服务撤销就绪状态并在限定时间内等待现有请求完成。

## 测试

- config_test.go：配置默认值、覆盖值和非法输入。
- logging_test.go：JSON 日志结构与级别校验。
- server_router_test.go：健康接口、中间件和统一错误。
- server_lifecycle_test.go：真实临时端口上的启动与退出。
