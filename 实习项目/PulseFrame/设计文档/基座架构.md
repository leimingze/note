# 基座架构

本文以 backend/cmd/pulseframe-api/main.go 中的 run 为主线，说明当前工程基座。

## 主流程

~~~mermaid
flowchart TD
    START([开始 run]) --> LOAD[config.Load]
    LOAD -- 失败 --> RETURNERR([返回错误])
    LOAD -- 成功 --> SIGNAL[signal.NotifyContext]
    SIGNAL --> LOGGER[logging.New]
    LOGGER -- 失败 --> RETURNERR
    LOGGER -- 成功 --> MODE[gin.SetMode]
    MODE --> HEALTH[server.NewHealthState]
    HEALTH --> ROUTER[server.NewRouter]
    ROUTER -- 失败 --> RETURNERR
    ROUTER -- 成功 --> SERVER[server.New]
    SERVER -- 失败 --> RETURNERR
    SERVER -- 成功 --> RUN[Server.Run]
    RUN --> STOP[撤销就绪状态并关闭服务]
    STOP --> DONE([run 返回])
~~~

## 直接调用

| 调用 | 作用 |
| --- | --- |
| config.Load(lookup) | 读取并校验环境、日志和 HTTP 配置 |
| signal.NotifyContext(...) | 将父上下文与终止信号合并为服务生命周期上下文 |
| logging.New(...) | 创建写入标准输出的 JSON 日志器 |
| ginMode(...) | 把项目环境映射为 Gin 模式 |
| gin.SetMode(...) | 设置 Gin 的进程级模式 |
| server.NewHealthState() | 创建 Router 和 Server 共用的健康状态 |
| server.NewRouter(...) | 注册基础中间件、健康接口和路由错误 |
| server.OptionsFromConfig(...) | 从配置生成 HTTP Server 参数 |
| server.New(...) | 校验参数并创建 Server |
| Server.Run(ctx) | 监听端口并运行到取消或错误 |

## 配置与日志

config.Load 使用 parseEnvironment、parseLogLevel 和 loadHTTP 生成类型化配置。loadHTTP 继续调用地址与时长校验函数。任一配置不合法时，服务不会开始监听。

logging.New 校验日志级别和输出目标，再创建 slog.JSONHandler。访问日志与异常恢复共用这个日志器。

## 路由

server.NewRouter 校验 Logger 和 Health，并依次创建请求标识、访问日志和异常恢复中间件。随后使用 gin.New 创建 Engine，关闭默认代理信任，并注册：

- GET /livez
- GET /readyz
- 404 处理函数
- 405 处理函数

当前路由不包含业务接口。

## Server 生命周期

server.New 根据 Options 创建标准库 http.Server。Server.Run 绑定监听地址后进入 Serve：

1. 发布就绪状态。
2. 启动 http.Server.Serve。
3. 等待服务错误或上下文取消。
4. 撤销就绪状态。
5. 收到取消时，在配置期限内调用 http.Server.Shutdown。

标准库正常关闭错误会转换为 nil；监听、服务或关闭错误会返回给 run。

## 当前边界

基座只提供运行能力，不连接 MySQL、Redis 或其他外部数据服务。未来业务需要存储时，应在对应设计中说明数据职责、故障影响和验证方式，再加入依赖。
