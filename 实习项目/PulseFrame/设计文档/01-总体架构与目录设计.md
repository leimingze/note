# 总体架构与目录设计

## 当前范围

PulseFrame 当前只保留可以独立运行和验证的核心 API 与网页工程基座。账号、视频、Feed 等业务尚未接入，数据库、缓存和消息系统也不属于当前运行依赖。

工程保留四类未来运行边界：

- 核心 API：普通 HTTP 业务接口。
- 事件 Worker：可靠异步任务和后台处理。
- 直播网关：长连接和实时消息。
- 内容安全 Agent：内容分析和受限工具调用。

后三类只在出现真实需求后创建。

## 当前目录

~~~text
PulseFrame/
├── backend/
│   ├── cmd/pulseframe-api/            # 核心 API 进程入口
│   ├── docs/                          # 后端运行说明
│   ├── internal/
│   │   ├── config/                    # 环境配置读取与校验
│   │   ├── logging/                   # JSON 日志器
│   │   ├── middleware/                # 请求标识、访问日志和异常恢复
│   │   ├── response/                  # 统一错误响应
│   │   └── server/                    # 健康状态、路由和服务生命周期
│   └── test/                          # 后端自动化测试
├── frontend/
│   ├── public/                        # 静态素材
│   └── src/                           # Vue 网页入口、页面和样式
├── memory/                            # 项目事实与决策记录
└── 设计文档/                          # 架构与源码阅读文档
~~~

只创建当前实现需要的目录。未来加入业务时，再根据业务职责增加代码位置和数据依赖。

## 请求流程

~~~text
HTTP 请求
  -> 请求标识
  -> 访问日志
  -> 异常恢复
  -> Gin 路由
  -> 健康 Handler 或统一路由错误
  -> HTTP 响应
~~~

Gin 只负责 HTTP 接入。配置、日志与 Server 生命周期位于独立 package，便于测试和后续复用。

## 运行基线

- 配置非法时拒绝启动，并返回具体配置名称。
- 每个请求带有关联标识，日志与错误响应可以互相对应。
- 内部异常只记录到服务日志，对外返回统一错误。
- /livez 表示进程可以响应，/readyz 表示实例可以接收流量。
- HTTP 读取、写入、空闲连接和退出过程都有明确期限。
- 收到终止信号后先撤销就绪状态，再等待现有请求完成。
- 源码和项目记忆不保存凭据。

## 后续业务

新增业务前需要完成需求、数据模型、接口、安全边界和验证方案设计。数据库、缓存或独立运行单元必须由实际数据与故障要求决定，不能仅为展示组件而引入。

业务代码的目录形式在开始实现时确定。ADR-0002 记录了此前采用横向分层的背景；当前没有业务代码，因此不会保留空的 Controller、Service 或 Repository 目录。
