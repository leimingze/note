# 登录与注册 · 执行计划

本文是「业务模块设计 / 登录与注册」的实现执行文档。整体方案与数据结构分别见 [登录与注册](登录与注册.md) 和 [登录与注册-数据结构](登录与注册-数据结构.md)。

按依赖关系拆分为六个独立块，每块完成并通过验证后再进入下一块，避免一次性铺开所有接口。

## 一、分块概览

| 序号 | 块 | 内容 | 依赖 |
| --- | --- | --- | --- |
| 1 | 数据层 | users、password_credentials 表与存储代码，Argon2id 哈希与验证 | 无 |
| 2 | 注册接口 | POST /api/register，输入校验、IP 限流、事务建用户 | 块1 |
| 3 | 密码登录 | POST /api/login，账号/IP 限流、密码验证、账号状态检查 | 块1、块2 |
| 4 | 令牌与会话 | JWT RS256、Access/Refresh、Redis 会话与轮换、/api/refresh、/api/logout | 块1、块3 |
| 5 | 封禁踢人 | users.status 与 auth_version 递增，会话失效 | 块4 |
| 6 | QQ 登录与绑定 | oauth state 一次性上下文、授权码换凭据、external_identities | 块1、块4 |

## 二、块1 数据层

目标：提供注册与登录所需的表结构、存储访问与密码哈希能力。

内容：

- 按数据结构文档创建 users、password_credentials 表，含约束与索引。
- 参数化查询：按 username 查询凭据、按 user id 查询用户、事务内创建用户与凭据。
- Argon2id 哈希生成与验证，哈希参数走配置。

验证：表结构与约束符合设计；存储代码有单元测试覆盖正常与异常路径。

完成定义：数据层代码与测试可用，注册和登录可直接调用。

## 三、块2 注册接口

目标：实现 POST /api/register。

内容：

- 输入校验：username 3-24 ASCII、password 12-128 Unicode。
- IP 规范与注册限流（rate:register:ip:{normalizedIp}）。
- 单事务创建 users 与 password_credentials，参数化写入。
- 响应：201 成功；409 用户名冲突；400 输入错误；503 依赖故障。

验证：覆盖成功、冲突、输入错误、限流命中与依赖故障场景。

完成定义：注册接口独立可用，不依赖登录。

## 四、块3 密码登录

目标：实现 POST /api/login 的账号校验与密码验证。

内容：

- 账号与 IP 双维度限流。
- 按 username 查询凭据并用 Argon2id 验证。
- 统一返回 401 INVALID_CREDENTIALS；disabled 返回 403。

验证：密码错误、账号禁用、限流、依赖故障均有对应响应。

完成定义：登录验证逻辑成立，会话发出在块4接入。

## 五、块4 令牌与会话

目标：接入长短令牌与会话生命周期。

内容：

- RS256 JWT 签名与验签、可信公钥配置。
- 会话与 refresh 映射的 Redis 原子 Lua 写入与轮换。
- /api/refresh 与 /api/logout。

验证：刷新轮换唯一成功、退出撤销、过期与禁用会话路径正确。

完成定义：登录返回令牌，刷新、退出闭环可用。

## 六、块5 封禁踢人

目标：实现封禁与全部退出。

内容：

- 更新 users.status 并递增 auth_version。
- 旧会话无法续期，恢复账号保留递增后版本。

验证：封禁后刷新被拒，恢复后旧会话仍不可用。

完成定义：封禁、恢复与版本语义符合设计。

## 七、块6 QQ 登录与绑定

目标：实现 QQ 登录与已有账号绑定。

内容：

- oauth:qq:state 一次性上下文与浏览器绑定凭据。
- 授权码换凭据并校验 openid，external_identities 关联。

验证：state 一次性消费、已有关联登录、绑定冲突与并发唯一约束。

完成定义：QQ 登录与绑定流程可用。

## 八、推进说明

每块完成后更新本文状态，并在「服务可用性与高并发治理.md」业务模块行同步进度。
