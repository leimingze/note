# 内容与发布：分期实施路线

## 背景

内容与发布是一个完整业务闭环，覆盖上传、创建、查询、审核、下架与删除，并且依赖账号会话、文件存储与独立审核平台。一次实现全部模块工程量大，也难以逐步验证正确性。本文将 [内容与发布](内容与发布.md) 与 [数据结构](内容与发布-数据结构.md) 的设计按依赖顺序分成阶段，每个阶段交付可运行、可测试的子集。

## 总原则

- 复用基座能力：JWT 鉴权、统一错误响应、结构化日志、MySQL/Redis、指标与请求上下文均沿用现有实现（见 `backend/internal/platform`）。
- 依赖未稳的模块不提前并行展开：Feed、播放、互动都以"已发布"数据为输入，必须先打通 上传 → 创建 → 提交 → 审核结论 → 公开可见。
- 不做空壳铺垫：Agent 初审、云存储直传、转码都放到专门阶段，现阶段不预留无用的占位实现。
- 每个阶段完成即可合并，并跑该阶段相关测试与接口冒烟。
- 事务边界是本模块的技术重点：**数据库事务内不发外部 HTTP 请求**，跨进程动作一律通过 outbox 与后台任务收敛。

## 分期计划

| 阶段 | 交付内容 | 涉及接口 / 表 | 完成标志 |
| --- | --- | --- | --- |
| P0 | 存储抽象、媒体探测与建表 | 存储接口、本地磁盘实现、ffprobe 封装、四张表迁移 | 迁移可重放，存储写入与超限拒绝有单测，探测对各类样本返回正确元数据 |
| P1 | 上传媒体与凭证 | POST /api/uploads、upload 表、限流与配额 | 合法文件返回凭证，非法文件 4xx 且无残留，重复内容去重生效 |
| P2 | 草稿、编辑与查询 | POST /api/videos、PATCH、GET 详情与两类列表 | 草稿不可见、可编辑；绑定校验拒绝越权 uploadId；列表过滤与游标正确 |
| P3 | 提交、撤回与审核对接 | submit、withdraw、webhook、投递 worker、对账任务、模拟桩 | 回调签名校验、轮次判新旧、重复回调幂等、投递失败可见可告警 |
| P4 | 下架、删除、恢复与清理 | 下架入口、DELETE、restore、清理任务、孤儿扫描 | 7 天内可恢复、逾期彻底删除、孤儿对象被回收、下架内容作者无法自行恢复 |
| P5 | 幂等、指标与稳定性 | 幂等中间件、指标与告警、集成与并发测试 | 重复提交不产生重复数据，指标可观测，关键并发路径无脏数据 |

### P0：存储抽象、媒体探测与建表

范围：

- 定义媒体存储接口：`Put(ctx, reader) (objectKey, error)`、`Delete(ctx, key)`、`URL(key) string`、`MaxBytes()`、`SignedURL(ctx, key, ttl) (string, error)`，以及双桶语义：`CopyToPublic(ctx, key)` / `DeletePublic(ctx, key)` / `PublicURL(key) string`；公开桶匿名可读、私有桶禁止匿名读。
- 对象键按最终字节内容寻址：`media/{ownerId}/{sha256前2位}/{sha256}.mp4`（封面 `.jpg`），`sha256` 取 faststart/remux 之后的最终字节。并发上传同一文件写同一 key，"对象只存一份"不依赖应用层去重逻辑。
- 本地磁盘实现支撑开发与联调（两个目录模拟两个桶），后续替换为 S3 兼容对象存储时只换实现。
- 封装媒体探测与处理：ffprobe 探测容器、视频编码、音频编码、时长、分辨率；ffmpeg 执行 MOV 重封装与 faststart。启动时检查两个二进制可用性，缺失则明确报错而非静默降级。
- 建立 `upload`、`video`、`video_stat`、`review_task` 四张表，含 `is_public` / `is_playable` 生成列、7 条状态/时间 CHECK、`pending_sha` 生成列与全部索引。
- 阈值提取为配置：视频单文件上限、封面单文件上限、时长上限、分辨率上限、小时/日次数与字节配额、faststart 超时、回收站保留天数、清理与扫描周期。

验收：

- 迁移脚本可重放（重复执行不报错，`is_public`、`pending_sha` 生成列与全部索引正确建立）。
- 约束有效：`status=2` 但 `published_at` 为空、`status=4` 但 `offline_at` 为空、`status=4` 且 `hidden_at` 非空、`status=1` 但 `submitted_at` 为空、`status=1` 但 `reject_reason` 非空，五类写入都必须被拒绝。
- 存储写入成功，超限写入被拒绝且无残留文件。
- 对 H.264+AAC MP4、无声 H.264 MP4、MOV、H.265、纯音频、损坏文件、超大文件七类样本，探测结果与预期一致。

### P1：上传媒体与凭证

范围：

- `POST /api/uploads`：JWT + `Idempotency-Key`，multipart 单文件。
- 流式落临时文件并计算 `source_sha256`，超限中断；探测失败或编码不支持时清理临时文件与已写对象。
- MOV 流复制重封装为 MP4；MP4/MOV 执行 faststart，对最终文件计算 `sha256` 作为对象键与完整性校验值，`size_bytes` 取最终大小。重封装或 faststart 失败按各自规则处理：重封装失败拒绝，faststart 超时降级原样存储。
- 同作者重复 `source_sha256` 不重复落对象：对象键由最终内容寻址决定，所以天然只有一份；凭证层面撞 `uk_upload_pending` 时回查未过期的待绑定记录返回，已过期则把旧行置 3 后插入新行。已绑定时另建一条记录，`media_key` 指向同一个内容键。
- 落 `upload` 记录（`source_sha256`、`sha256`、最终 `size_bytes`、`status=1`、`expires_at=now+24h`），返回 `uploadId`、时长、宽高与建议封面；`?kind=image` 时只处理封面图并映射为 `kind=2`。
- 上传限流与配额（Redis 计数），超限 429 并带 `Retry-After`。

验收：

- 正常文件返回 200 与完整元数据；格式/编码/时长/分辨率超限分别返回对应 4xx 错误码。
- 失败调用后临时目录与媒体目录均无残留。
- 相同文件二次上传：未绑定时复用 uploadId；已绑定时新建凭证但对象只存一份。faststart 改变大小时，`sha256` 与 `size_bytes` 对应最终对象，`source_sha256` 对应原始文件。
- MOV 上传后对象可播放、`content_type=video/mp4`，不存在 MOV 字节写进 `.mp4` 键的情况。
- **并发同一文件**：10 并发上传同一文件，最终只有 1 条待绑定 upload 记录、存储层只有 1 个对象；失败者返回同一个 `uploadId` 而非 500。
- 超过小时配额后返回 429。

### P2：草稿、编辑与查询

范围：

- `POST /api/videos`：body 必含 `uploadId`（缺失或 kind=2 → 422 `VIDEO_MEDIA_REQUIRED`），事务内校验归属、`status=1`、`kind=1`，从 upload 复制媒体元数据，插入 `video(status=0)` 与 `video_stat(全零)`，用 `UPDATE upload SET status=2 WHERE id=? AND status=1` 置为已绑定并检查影响行数。
- 封面凭证 `coverUploadId`（可选）：校验归属、`status=1`、`kind=2`，复制 `cover_key` 并记录 `video.cover_upload_id`，同事务条件更新该凭证为已绑定。
- `PATCH /api/videos/{videoId}`：仅 `status ∈ {0,3}` 可改 `title`、`description`、`coverUploadId`；换封面时同一事务绑定新凭证，旧 `cover_upload_id` 非空才置 `status=3`、`expires_at=now()`，影响行数为 0 返回 409；旧封面来自自动抽帧时只替换 `cover_key`。
- `GET /api/videos/{videoId}`：作者可见自己全部状态，他人仅 `is_playable=1`，否则 404。
- `GET /api/users/{userId}/videos`：只看 `is_playable=1`，`(published_at, id)` 游标分页。
- `GET /api/users/me/videos`：可按 `status` 过滤，默认排除回收站，`?scope=recycle` 单查回收站。
- `GET /api/videos/{videoId}/playback`：`is_playable=1` 返回公开桶直链；作者访问自己的非公开视频返回私有桶短时签名（TTL 10 分钟）；其余 404。列表返回的播放与封面地址统一走这个函数，不在列表里拼裸对象键。

验收：

- 草稿在他人视角 404、在作者视角可见且可反复编辑。
- 使用他人 `uploadId`、已绑定 `uploadId`、`kind=2` 的封面凭证作主媒体、或客户端直传对象键均返回 409 `UPLOAD_NOT_BINDABLE`；缺少 `uploadId` 返回 422。
- 封面凭证绑定后不会被孤儿扫描回收：`video.cover_upload_id` 有引用，扫描时跳过；换封面后旧凭证进入 `status=3` 并在过期后被回收，旧对象无其他引用时删除。
- 同一封面凭证并发绑定到两个视频时，只有一个成功，另一个返回 409，`uk_video_cover_upload` 生效。
- 列表游标翻页无重复、无遗漏，插入新记录不影响既有游标位置。
- 提交后（P3）PATCH 返回 409。

### P3：提交、撤回与审核对接

前提：审核由独立平台负责，本站不引入管理员角色，作者只管理自己的视频。

范围：

- `POST /api/videos/{videoId}/submit`：校验完整性后单事务翻状态、写 `submitted_at`、`review_round+1`、插入 `review_task(status=1)`。**事务内不调用审核平台。**
- 投递 worker 三段式，外部调用一律在事务外：
  1) 领取（短事务，无外部调用）：`UPDATE review_task SET status=2 投递中, lease_owner=批次令牌, lease_expires_at=now+lease_seconds, attempt_count=attempt_count+1 WHERE status=1 AND next_attempt_at<=now() ORDER BY next_attempt_at LIMIT 20`；`lease_seconds = 批次条数 × 单条超时 + 30s`，默认 20×10+30=230 秒。按批次令牌回查本批任务。
  2) 投递（事务外）：逐条调审核平台（10s 超时），带 `X-Idempotency-Key: review-task-{id}` 与 `client_task_id={id}`；成功 → `status=3` + `external_task_id`，若任务已被撤回/删除置 7 则只写 `external_task_id` 并保持 7；失败且 `attempt_count<5` → 回 `status=1` 并指数退避；≥5 → `status=6` 投递失败并告警。成功写回带 `AND status IN (2,7) AND lease_owner=批次令牌`，失败写回只允许 `status=2`。
  3) 扫尾（每分钟）：`lease_expires_at<now() AND status=2` 退回 `status=1`，接管 worker 崩溃留下的悬挂记录。
- `POST /api/videos/{videoId}/withdraw`：`status=1 → 0`，清 `submitted_at` 与 `reject_reason`，本轮任务 `status ∈ {1,2,3}` 全部置 `status=7` 本地已撤销；3 外部已在审，置 7 后迟到回调只写任务结论。
- `POST /api/review/webhook`：HMAC-SHA256 签名 + 5 分钟时间窗口；先按 `external_task_id` 定位，查不到再用 `client_task_id` 定位并补写；校验 `review_round` 命中当前轮次且 `status ∈ {3,7}`，轮次不匹配或任务已 4/5 返回 200 并记 warn。任务 3 时以 `WHERE id=? AND status=1 AND review_round=? AND deleted_at IS NULL` 更新视频；任务 7 只写任务结论，不改视频。
- 对账任务：扫描 `status IN (3,7)` 且已有 `external_task_id`、`created_at` 超过 10 分钟的记录，主动查询审核平台拉结论；任务为 7 时只写任务结论。与投递链路互不干扰：投递看 `status=1/2`，对账看 `status=3/7`。
- 本地模拟桩：自动通过或随机驳回，支持配置延迟与失败率，便于验证重试与对账。

验收：

- 无签名、错签名、过期时间戳均返回 401。
- 通过后视频进入公开列表且 `published_at` 被写入；驳回后作者可见 `reject_reason`，他人仍 404。
- 同一回调重复投递 3 次，状态与计数不变。
- 领取不重复：20 个 worker 并发领取同一批 10 条任务，每条只被一个 worker 领到，`attempt_count` 递增总量等于实际投递次数。
- 崩溃接管：投递中途 kill worker，60 秒后扫尾任务把记录退回待投递并被其他 worker 接管；反复崩溃 5 次后落到 `status=6` 并告警，不无限重试。
- 批次租约：20 条任务、每条 10 秒超时，整批处理完成前没有任何任务被扫尾回收；把租约改成 60 秒时该用例必须失败，证明测试能发现配置不匹配。
- 投递幂等：平台已接收但本地超时，重试携带同一 `X-Idempotency-Key`，平台返回同一 `external_task_id`，最终只有一个外部任务。
- 取消与在途投递竞争：worker 已发出请求后作者撤回，worker 成功返回仍写入 `external_task_id` 并保持 7；回调按 `client_task_id` 定位，任务结论落库、视频保持草稿。
- 新任务立即可领：提交后 `next_attempt_at` 有值，无需等待即可被领取（回归测试覆盖 `NULL` 哑火）。
- 撤回后重新提交产生 `review_round+1` 的新任务；旧轮次迟到回调被忽略，视频状态不被覆盖。
- 撤回不重新提交：任务已到 `status=3` 后撤回，迟到通过回调到达，视频保持 `status=0`，只更新任务结论。
- 模拟桩配置为持续失败时，任务进入 `status=6` 并触发告警指标。

### P4：下架、删除、恢复与清理

范围：

- 平台下架入口 `POST /internal/videos/{videoId}/offline`（管理后台属后续模块）：调用方携带服务间凭证，请求体含 `operator_id`、`reason`；`status=2 → 4`，**同一语句**写 `offline_at`、`offline_reason` 并清空 `hidden_at`（`chk_video_hidden` 要求非 2 状态不得有 `hidden_at`，不下架隐藏中的视频会直接写失败）；写结构化审计日志（operator、video、前后状态、理由）；下架为终态，后续所有状态更新语句统一带 `status <> 4`。`is_public` 立即变 0，公开桶副本由请求路径尽力删除、对账任务兜底，私有桶保留作取证。
- `DELETE /api/videos/{videoId}`：作者本人，任意状态 → 写 `deleted_at`，同事务把当前轮 `review_task(status IN (1,2,3))` 置 7 本地已撤销；`is_public` 立即变 0，公开桶副本尽力删除；回收站保留 7 天。已下架内容同样可被作者删除，但删除不改变下架结论。
- `POST /api/videos/{videoId}/restore`：`deleted_at` 非空且未超 7 天 → 清 `deleted_at`；`status=1` 时同一语句改回 `status=0` 并清 `submitted_at`、`reject_reason`，因为当前轮任务已置 7，恢复后不会再有 worker 投递；其他状态保持原值，`status=4` 恢复后仍不可见。
- 清理任务（每小时，Redis 分布式锁保证单实例）：`deleted_at < now-7d`，分两个事务阶段：
  阶段一按外键逆序删除 `review_task → video_stat → video → upload`（`upload` 必须最后：`video.upload_id`、`video.cover_upload_id` 都 RESTRICT 引用它）；
  阶段二在事务外对 `media_key`/`cover_key` 做引用计数，无引用才删对象（含公开桶副本），有引用则保留。
  阶段一可重入，阶段二失败交孤儿扫描兜底。
- 公开桶同步（每 30 秒）：扫描 `is_public=1 AND public_object_present=0` 复制到公开桶，扫描 `is_public=0 AND public_object_present=1` 删除公开桶副本；成功更新 `public_object_present`，失败告警并下轮重试。列表与播放只认 `is_playable`，复制完成前不返回公开地址。
- CDN 刷新：部署启用 CDN 时，公开桶复制与删除后调用刷新接口；本地磁盘与未接 CDN 的环境由存储实现返回成功并跳过，不改变业务调用方式。
- 孤儿扫描（每小时）：清理 `status IN (1,3) AND expires_at < now()` 的 upload 记录，但必须排除被 `video.upload_id` 或 `video.cover_upload_id` 引用的行（外键 RESTRICT 也会挡住，扫描应先过滤避免整批失败）；删除对象前先确认 `media_key`、`cover_key` 无其他 upload/video 引用（内容寻址下别的凭证可能共用同一 key），并按标记后延迟 24 小时的两阶段删除执行。
- 对象引用对账（每小时）：列举私有桶与公开桶对象，与 upload/video 的对象键比对；无数据库引用且创建超过 24 小时的对象删除，覆盖"Put 成功但 insert 失败"和"purge 后对象删除失败"。

验收：

- 删除后他人 404、作者在回收站可见；6 天后恢复成功且回到原状态与原本的时间位置。
- 删除待审核视频后恢复：状态变为草稿，`submitted_at`、`reject_reason` 为空，可以直接重新提交；不会停留在没有任务的待审核。
- 8 天后记录被物理删除，`review_task`、`video_stat`、`video`、对应的 `upload`（含 `cover_upload_id` 那行）全部无残留，无引用的存储对象已清理。
- 下架隐藏中的视频：下架成功且 `hidden_at` 被清空；不加清理逻辑时会因 CHECK 约束写失败，这条用例守住该回归。
- 未绑定且过期的上传记录被回收；两个 upload 共享同一对象时，删前者不影响后者的媒体可访问。
- 下架内容作者无法通过 visibility、submit、restore 任一接口恢复可见，均返回 409。
- 下架后 `is_playable=0`，接口不再返回公开地址；公开桶副本在对账周期内删除，私有桶对象仍在（可用于复审与申诉）。
- 公开桶同步失败时 `public_object_present` 保持 0，列表不返回该视频，告警指标累加；对账恢复后自动变为可播放。
- 上传成功但写库失败、或清理后对象删除失败时，对象引用对账能把无引用对象删除。

### P5：幂等、指标与稳定性

范围：

- 幂等中间件：`Idempotency-Key` 落 Redis，覆盖 uploads、videos、submit、withdraw、visibility、delete、restore；同键同指纹返原响应，同键不同指纹 409；创建与判定用 Lua 原子完成。
- 指纹规范化：JSON 按字典序序列化后取哈希；**multipart 必须按语义拼接**（method+path+kind+文件名+`source_sha256`），不能对原始请求体取哈希——boundary 随机，否则同一文件每次都被判成新请求。原始文件哈希复用读取上传流时的计算结果，不二次读盘；faststart 后的最终哈希不参与指纹。
- 幂等键只包住"确实需要"的写接口：upload 与 create 是用户重试高发点，submit/withdraw/delete/restore 是状态机操作，重复提交会返回 409 而非 500。
- Redis 不可用时直接放行并打告警：放弃幂等保证，避免写路径整体不可用；多余记录由用户删除兜底。
- 指标落地：上传结果与耗时、探测与 faststart 耗时、提交与投递结果、回调结果与审核时长、待审核最老记录时长、清理滞后、孤儿数量。
- 指标补充：公开桶同步滞后与失败数、无引用对象数量；上传字节配额按 `Content-Length` 预留、失败回退。
- 告警：待审核最老记录超过 30 分钟、投递失败数 > 0、公开桶同步失败或滞后超过 5 分钟、清理滞后超过 2 小时、回调失败率超过 1%。
- 集成与并发测试：并发提交同一视频、并发回调、删除与回调竞争、撤回与回调竞争。

验收：

- 同一 `Idempotency-Key` 重复调用只产生一条记录，第二次响应与第一次一致。
- 同一文件用同一幂等键上传两次（客户端换了 boundary），第二次仍命中缓存响应，不产生第二条记录；这是 multipart 指纹最容易错的地方。
- 并发上传各声明不同 `Content-Length`：预留总量超过 2GB/日时，超出者直接 429，不会在读完后才发现超限。
- 业务事务已提交但响应写出失败：幂等键保留为 done，客户端重试返回首次状态码，不产生第二条记录。
- 10 并发提交同一视频只有 1 个成功，其余 409，无重复 `review_task`。
- 删除与回调并发时，最终状态要么"已删除"、要么"已删除且回写已落库"，两种都不出现可见内容残留；删除后不再有新的投递。
- 指标在 `/metrics` 上可查，告警规则可触发。

## 通用约定

- 业务路由统一挂在 `/api` 前缀下，鉴权沿用登录模块 JWT；作者身份一律取自登录态，不取请求参数。
- 事务规则：创建时 `video` + `video_stat` + `upload` 同事务；提交时 `video` + `review_task` 同事务；**任何事务内不做外部 HTTP 调用**。
- 状态变更一律用条件更新（`WHERE status IN (...)`），以受影响行数判断冲突，禁止"先查后写"。
- 物理删除按 `review_task → video_stat → video → upload` 顺序执行，避免外键 RESTRICT 阻断；对象删除必须放在数据库删除之后，并且先做引用计数。
- 媒体可见性由存储层保证：公开桶副本由对账任务在审核通过后写入、在下架/隐藏/删除后删除；私有桶永不匿名可读。任何接口都不得把私有桶的裸对象键直接返回给客户端。
- 每个阶段收尾时更新项目状态索引，记录完成内容、验证情况与下一阶段。
- 阈值、配额、超时全部走配置，不写死常量；本地开发用宽松值，生产用默认值并留压测校准记录。
