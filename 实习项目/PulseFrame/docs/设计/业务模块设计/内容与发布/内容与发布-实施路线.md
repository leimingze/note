# 内容与发布：分期实施路线

## 背景

内容与发布是一个完整业务闭环，覆盖上传、创建、查询、审核、下架与删除，并且依赖账号会话、文件存储与独立审核平台。一次实现全部模块工程量大，也难以逐步验证正确性。本文将 [内容与发布](内容与发布.md) 与 [数据结构](内容与发布-数据结构.md) 的设计按依赖顺序分成阶段，每个阶段交付可运行、可测试的子集。

## 总原则

- 复用基座能力：JWT 鉴权、统一错误响应、结构化日志、MySQL/Redis、指标与请求上下文均沿用现有实现（见 `backend/internal/platform`）。
- 依赖未稳的模块不提前并行展开：Feed、播放、互动都以"已发布"数据为输入，必须先打通 上传 → 创建 → 提交 → 审核结论 → 公开可见。
- 不做空壳铺垫：Agent 初审、云存储直传、转码都放到专门阶段，现阶段不预留无用的占位实现。
- 每个阶段完成即可合并，并跑该阶段相关测试与接口冒烟。
- 事务边界是本模块的技术重点：**数据库事务内不发外部 HTTP 请求**，跨进程动作一律通过 outbox 与后台任务收敛。

## 分期计划

| 阶段 | 交付内容 | 涉及接口 / 表 | 完成标志 |
| --- | --- | --- | --- |
| P0 | 存储抽象、媒体探测与建表 | 存储接口、本地磁盘实现、ffprobe 封装、四张表迁移 | 迁移可重放，存储写入与超限拒绝有单测，探测对各类样本返回正确元数据 |
| P1 | 上传媒体与凭证 | POST /api/uploads、upload 表、限流与配额 | 合法文件返回凭证，非法文件 4xx 且无残留，重复内容去重生效 |
| P2 | 草稿、编辑与查询 | POST /api/videos、PATCH、GET 详情与两类列表 | 草稿不可见、可编辑；绑定校验拒绝越权 uploadId；列表过滤与游标正确 |
| P3 | 提交、撤回与审核对接 | submit、withdraw、webhook、投递 worker、对账任务、模拟桩 | 回调签名校验、轮次判新旧、重复回调幂等、投递失败可见可告警 |
| P4 | 下架、删除、恢复与清理 | 下架入口、DELETE、restore、清理任务、孤儿扫描 | 7 天内可恢复、逾期彻底删除、孤儿对象被回收、下架内容作者无法自行恢复 |
| P5 | 幂等、指标与稳定性 | 幂等中间件、指标与告警、集成与并发测试 | 重复提交不产生重复数据，指标可观测，关键并发路径无脏数据 |

### P0：存储抽象、媒体探测与建表

范围：

- 定义媒体存储接口：`Put(ctx, reader) (objectKey, error)`、`Delete(ctx, key)`、`URL(key) string`、`MaxBytes()`。
- 本地磁盘实现支撑开发与联调，按日期分目录；后续替换为 S3 兼容对象存储时只换实现。
- 封装媒体探测：容器、视频编码、音频编码、时长、分辨率。优先使用纯 Go 库；确需外部二进制时用 ffprobe，并在启动时探测可用性、不可用则明确报错而非静默降级。
- 建立 `upload`、`video`、`video_stat`、`review_task` 四张表，含 `is_public` 生成列与全部索引。
- 阈值提取为配置：单文件上限、时长上限、分辨率上限、小时/日次数与字节配额、faststart 超时、回收站保留天数、清理与扫描周期。

验收：

- 迁移脚本可重放（重复执行不报错，`is_public` 生成列与索引均正确建立）。
- 存储写入成功，超限写入被拒绝且无残留文件。
- 对 H.264+AAC MP4、MOV、H.265、纯音频、损坏文件、超大文件六类样本，探测结果与预期一致。

### P1：上传媒体与凭证

范围：

- `POST /api/uploads`：JWT + `Idempotency-Key`，multipart 单文件。
- 流式落临时文件并计算 sha256，超限中断；探测失败或编码不支持时清理临时文件与已写对象。
- 同作者重复 sha256 不重复落对象：存在未绑定（`status=1`）的同指纹记录时直接复用该 `uploadId`；已绑定时另建一条记录复用同一 `media_key`，保证凭证可用且对象只有一份。
- faststart：`moov` 已前置则跳过；需重写则流式处理，超过 10s 降级为原样存储并记 warn。
- 落 `upload` 记录（`status=1`、`expires_at=now+24h`），返回 `uploadId`、时长、宽高与建议封面；`?kind=image` 时只处理封面图并映射为 `kind=2`。
- 上传限流与配额（Redis 计数），超限 429 并带 `Retry-After`。

验收：

- 正常文件返回 200 与完整元数据；格式/编码/时长/分辨率超限分别返回对应 4xx 错误码。
- 失败调用后临时目录与媒体目录均无残留。
- 相同文件二次上传复用记录、对象只存一份。
- 超过小时配额后返回 429。

### P2：草稿、编辑与查询

范围：

- `POST /api/videos`：body 含 `uploadId`，事务内校验归属与状态，从 upload 复制媒体元数据，插入 `video(status=0)` 与 `video_stat(全零)`，置 `upload.status=2`。
- `PATCH /api/videos/{videoId}`：仅 `status ∈ {0,3}` 可改 `title`、`description`、`coverUploadId`；封面凭证同样校验归属与绑定状态，影响行数为 0 返回 409。
- `GET /api/videos/{videoId}`：作者可见自己全部状态，他人仅 `is_public=1`，否则 404。
- `GET /api/users/{userId}/videos`：只看 `is_public=1`，`(published_at, id)` 游标分页。
- `GET /api/users/me/videos`：可按 `status` 过滤，默认排除回收站，`?scope=recycle` 单查回收站。

验收：

- 草稿在他人视角 404、在作者视角可见且可反复编辑。
- 使用他人 `uploadId`、已绑定 `uploadId` 或客户端直传对象键均返回 409 `UPLOAD_NOT_BINDABLE`。
- 列表游标翻页无重复、无遗漏，插入新记录不影响既有游标位置。
- 提交后（P3）PATCH 返回 409。

### P3：提交、撤回与审核对接

前提：审核由独立平台负责，本站不引入管理员角色，作者只管理自己的视频。

范围：

- `POST /api/videos/{videoId}/submit`：校验完整性后单事务翻状态、写 `submitted_at`、`review_round+1`、插入 `review_task(status=1)`。**事务内不调用审核平台。**
- 投递 worker：`SELECT ... FOR UPDATE SKIP LOCKED` 拉待投递任务，调用审核平台；成功置 `status=2` 写 `external_task_id`；失败按指数退避重试，超 5 次置 `status=5` 并告警。
- `POST /api/videos/{videoId}/withdraw`：`status=1 → 0`，清 `submitted_at`，本轮任务置 `status=6`。
- `POST /api/review/webhook`：HMAC-SHA256 签名 + 5 分钟时间窗口；按 `external_task_id` 定位任务；校验 `review_round` 与 `status=2`，不满足返回 200 并记 warn；满足则在事务内回写任务与视频状态。
- 对账任务：扫描 `status=2` 且 `created_at` 超过 10 分钟的记录，主动查询审核平台拉结论。
- 本地模拟桩：自动通过或随机驳回，支持配置延迟与失败率，便于验证重试与对账。

验收：

- 无签名、错签名、过期时间戳均返回 401。
- 通过后视频进入公开列表且 `published_at` 被写入；驳回后作者可见 `reject_reason`，他人仍 404。
- 同一回调重复投递 3 次，状态与计数不变。
- 撤回后重新提交产生 `review_round+1` 的新任务；旧轮次迟到回调被忽略，视频状态不被覆盖。
- 模拟桩配置为持续失败时，任务进入 `status=5` 并触发告警指标。

### P4：下架、删除、恢复与清理

范围：

- 平台下架入口（本期通过内部接口或运维脚本，管理后台属后续模块）：`status=2 → 4`，写 `offline_at`、`offline_reason`；下架为终态，后续所有状态更新语句统一带 `status <> 4`。
- `DELETE /api/videos/{videoId}`：作者本人，任意状态 → 写 `deleted_at`，同事务把当前轮 `review_task(status=1/2)` 置 6 已撤销，回收站保留 7 天；已下架内容同样可被作者删除，但删除不改变下架结论。
- `POST /api/videos/{videoId}/restore`：`deleted_at` 非空且未超 7 天 → 清 `deleted_at`，回到原状态；`status=4` 的记录恢复后仍为已下架，不可见。
- 清理任务（每小时，Redis 分布式锁保证单实例）：`deleted_at < now-7d`，按 `review_task → video_stat → video` 顺序物理删除，再删存储对象；对象删除失败只记日志，交孤儿扫描兜底。
- 孤儿扫描（每小时）：清理 `status=1 AND expires_at < now()` 的 upload 记录；删除对象前先确认 `media_key`、`cover_key` 无其他 upload/video 引用（去重共享对象），并按标记后延迟 24 小时的两阶段删除执行。

验收：

- 删除后他人 404、作者在回收站可见；6 天后恢复成功且回到原状态与原本的时间位置。
- 8 天后记录被物理删除，`review_task`、`video_stat` 无残留，存储对象已清理。
- 未绑定且过期的上传记录被回收；两个 upload 共享同一对象时，删前者不影响后者的媒体可访问。
- 下架内容作者无法通过 visibility、submit、restore 任一接口恢复可见，均返回 409。

### P5：幂等、指标与稳定性

范围：

- 幂等中间件：`Idempotency-Key` 落 Redis，覆盖 uploads、videos、submit、withdraw、visibility、delete、restore；同键同指纹返原响应，同键不同指纹 409；创建与判定用 Lua 原子完成，避免竞态。
- 幂等键只包住"确实需要"的写接口：upload 与 create 是用户重试高发点，submit/withdraw/delete/restore 是状态机操作，重复提交会返回 409 而非 500。
- Redis 不可用时直接放行并打告警：放弃幂等保证，避免写路径整体不可用；多余记录由用户删除兜底。
- 指标落地：上传结果与耗时、探测与 faststart 耗时、提交与投递结果、回调结果与审核时长、待审核最老记录时长、清理滞后、孤儿数量。
- 告警：待审核最老记录超过 30 分钟、投递失败数 > 0、清理滞后超过 2 小时、回调失败率超过 1%。
- 集成与并发测试：并发提交同一视频、并发回调、删除与回调竞争、撤回与回调竞争。

验收：

- 同一 `Idempotency-Key` 重复调用只产生一条记录，第二次响应与第一次一致。
- 10 并发提交同一视频只有 1 个成功，其余 409，无重复 `review_task`。
- 删除与回调并发时，最终状态要么"已删除"、要么"已删除且回写已落库"，两种都不出现可见内容残留；删除后不再有新的投递。
- 指标在 `/metrics` 上可查，告警规则可触发。

## 后续阶段（不属于本期必须）

- 转码与多码率：新增 `media_transcode_task`，发布前产出多档清晰度与标准封面；届时放宽编码校验，接受 H.265 等客户端默认格式。
- 客户端直传对象存储：upload 改为返回预签名 URL，新增 `POST /api/uploads/complete` 由服务端回查对象并补全元数据，绑定与清理逻辑不变。
- 断点续传：分片上传 + 断点记录，仍是 `upload` 表的一行，只增加分片清单。
- 内容安全 Agent：复用 `review_task`，以 `review_source` 区分审核方；同一视频可并行多审核方，结论合并规则在业务层实现，不改表结构。
- 弹幕审核：同一套待审实体与决策记录再扩展。
- 管理后台：下架、申诉、审核记录查询，属于运营模块。
- 详情缓存与 Feed 发件箱：按 [内容与发布](内容与发布.md) 的演进路径推进。

## 通用约定

- 业务路由统一挂在 `/api` 前缀下，鉴权沿用登录模块 JWT；作者身份一律取自登录态，不取请求参数。
- 事务规则：创建时 `video` + `video_stat` + `upload` 同事务；提交时 `video` + `review_task` 同事务；**任何事务内不做外部 HTTP 调用**。
- 状态变更一律用条件更新（`WHERE status IN (...)`），以受影响行数判断冲突，禁止"先查后写"。
- 物理删除按 `review_task → video_stat → video` 顺序执行，避免外键 RESTRICT 阻断。
- 每个阶段收尾时更新项目状态索引，记录完成内容、验证情况与下一阶段。
- 阈值、配额、超时全部走配置，不写死常量；本地开发用宽松值，生产用默认值并留压测校准记录。
