# 内容与发布：分期实施路线

## 背景

内容与发布是一个完整业务闭环，覆盖上传、创建、查询、审核、下架与删除，并且依赖账号会话、文件存储与独立审核平台。一次实现全部模块工程量大，也难以逐步验证正确性。本文将 [内容与发布](内容与发布.md) 与 [数据结构](内容与发布-数据结构.md) 的设计按依赖顺序分成阶段，每个阶段交付可运行、可测试的子集，方便逐步推进。

## 总原则

- 复用基座能力：JWT 鉴权、统一错误响应、结构化日志、MySQL/Redis 与请求上下文均沿用现有实现。
- 依赖未稳的模块不提前并行展开：Feed、播放、互动都以"已发布"数据为输入，必须先打通 上传 → 创建 → 审核 → 公开可见。
- 不做空壳铺垫：Agent 初审、云存储、断点续传都放到专门阶段，现阶段不预留无用的占位实现。
- 每个阶段完成即合并，并跑该阶段相关的测试与接口冒烟。

## 分期计划

| 阶段 | 交付内容 | 涉及接口 / 表 | 完成标志 |
| --- | --- | --- | --- |
| P0 | 存储抽象与建表 | 存储接口、本地磁盘实现、video / video_stat / review_task 迁移 | 迁移可运行，存储写入与拒绝有单测 |
| P1 | 上传媒体 | POST /api/uploads | 合法文件返回媒体地址，非法文件返回 4xx 且无残留 |
| P2 | 草稿、提交与查询 | POST /api/videos、PATCH /api/videos/{id}、POST …/submit、列表 | 草稿与提交分离正确，提交时三表事务一致 |
| P3 | 审核平台对接 | 送审记录、回调入口、本地模拟桩 | 回调签名校验，状态随审核结果流转，重复回调幂等 |
| P4 | Feed 接入与稳定性 | 只读已发布且未隐藏/未删除列表、回收站恢复、超期清理、幂等键、统一错误 | 端到端链路可跑，测试覆盖基本路径 |

### P0：存储抽象与建表

范围：

- 定义媒体存储接口（写入、返回稳定地址、拒绝大文件）。
- 使用本地磁盘实现支撑开发与联调，后续可替换为 S3 兼容对象存储。
- 建立 video、video_stat、review_task 三张表。
- 将上传大小上限等阈值提取为配置常量。

验收：迁移脚本可重放；存储权限在参数范围内通过，越界直接拒绝；接口变化不波及业务代码。

### P1：上传媒体

范围：

- `POST /api/uploads` 接收文件，校验扩展名、MIME、大小、时长、分辨率和编码。
- 写入存储并返回媒体地址；MP4/MOV 执行 faststart。
- 校验失败时清理已写入文件，避免残留。

验收：正常文件返回 200 与地址；非法格式或超限返回 4xx；失败调用后媒体目录无残留。

### P2：草稿、提交与查询

范围：

- `POST /api/videos`：创建草稿，标题可选。
- `PATCH /api/videos/{videoId}`：更新草稿，补全标题、简介与媒体地址。
- `POST /api/videos/{videoId}/submit`：提交审核，校验完整性后写入 submitted_at 与待审核状态。
- 提交审核时在同一事务写入 video_stat 与送审记录，失败整体回滚。
- `GET /api/videos/{id}`：视频详情。
- `GET /api/users/{userId}/videos`：公开作品列表，只返回已发布内容。
- `GET /api/users/me/videos`：我的作品列表，返回自己名下状态。

验收：草稿不对外可见且可编辑，提交后进入待审核；详情与列表过滤正确；并发创建与提交不丢失且不产生脏数据。

### P3：审核平台对接

前提：审核由独立平台负责，本站不引入管理员角色，作者只管理自己的视频。

范围：

- 保留 `POST /api/review/webhook` 回调入口，校验来源签名后接收通过或驳回决定。
- 回写 video 状态与驳回原因，重复回调幂等。
- 提供本地模拟桩，自动通过或驳回送审内容，便于开发期验证完整链路。
- `DELETE /api/videos/{videoId}`：仅作者逻辑删除自己的视频。

验收：回调签名不合法被拒绝；通过后公开列表可见；驳回后作者可见原因；重复回调结果一致；非作者删除返回 403。

### P4：Feed 接入与稳定性

范围：

- Feed 只读取"已发布"状态，保证公开内容可见且一致。
- `POST /api/videos/{videoId}/restore`：从回收站恢复 7 天内的视频。
- 定期清理任务：扫描并彻底删除超出 7 天的回收站记录，同时清理媒体与关联记录。
- 补齐写接口幂等键与统一错误响应。
- 补集成与并发测试，覆盖创建、审核、列表、删除等关键路径。

验收：用户发布后可在公开列表看到，审核前不可见，隐藏后他人不可见；7 天内可恢复，逾期被清理；基本并发路径无异常。

## 后续阶段（不属于本期必须）

- Agent 初审：复用 review_task 实体追加实现，不改动现有状态模型。
- 弹幕审核：在同一套待审实体与决策记录上扩展。
- 云对象存储切换：仅替换存储实现，业务代码不变。
- 上传进度与断点续传：本期不规划，短视频使用单次整传，失败整文件重传。

## 通用约定

- 业务路由统一挂在 /api 前缀下，鉴权沿用登录模块 JWT。
- 创建视频必须在一个事务内写入 video、video_stat、review_task，任何失败整体回滚。
- 写接口需要幂等支持的在接口表标注幂等键。
- 每个阶段收尾时更新项目状态索引，记录完成内容、验证情况与下一阶段。
