# 视频发布模块·参考项目合并

本文把 douyin、MChecker、GCFeed 三个参考项目中与视频发布相关的能力合并，作为 PulseFrame《内容与发布》系列的实现补充。PulseFrame 的需求、数据模型和接口仍以现有设计文档为准，本文只说明每个参考项目能提供什么、放到哪一步。

## 一、来源盘点与定位

| 来源 | 具备能力 | 形态 | 对 PulseFrame 的定位 |
| --- | --- | --- | --- |
| douyin | 发布页交互框架：摄像头预览、分段拍/快拍/影集/开直播切换 | Vue3 前端单页，接口全部 mock | 前端发布交互参考，不提供真实发布链路 |
| MChecker | 后端视频处理：ffmpeg 抽帧、分段分析、多模态审核 | FastAPI 后端 | 内容审核 Agent 接入时的预处理与抽帧参考 |
| GCFeed | 完整发布业务：发布、详情、列表、上传、软删除、审核 | Go API 单体 + MySQL/Redis | 后端发布链路的工程结构参考 |

三个来源中，只有 GCFeed 具备完整的发布后端链路；douyin 的发布页只是录制与预览外壳，没有上传或提交接口；MChecker 只消费视频用于审核，不产生视频发布。

## 二、合并到执行计划

以下把参考能力合并到《内容与发布-执行计划》的七个块。

| 块 | 合并内容 | 来源 |
| --- | --- | --- |
| 块2 存储接口 | 参考 GCFeed 的存储抽象方向，定义 Storage 接口与本地磁盘实现 | GCFeed |
| 块3 上传接口 | 校验、faststart 与失败清理按 PulseFrame 设计落地；参考 GCFeed 上传入口与文件处理 | GCFeed |
| 块4 创建视频 | 事务创建 video、video_stat、review_task 按 PulseFrame 数据结构落地 | GCFeed |
| 块5 人工审核 | 审核任务、决策日志与状态流转按 PulseFrame 设计落地；Agent 初审预留接口 | GCFeed、MChecker |
| 块6 详情与列表 | 详情、公开列表、我的作品接口 | GCFeed |
| 块7 删除与状态 | 软删除、下架与状态流转 | GCFeed |
| 前端交互 | 采集 douyin Publish 页的拍摄与预览交互，替换为上报进度的单请求上传 | douyin |

## 三、前端发布交互合并

douyin 的 src/pages/home/Publish.vue 提供拍摄、预览和模式切换。PulseFrame 目前的模块不进剪辑、滤镜与特效，因此只借鉴其交互骨架：顶部关闭、模式切换、工具栏。真实上传按 PulseFrame 设计改为调用 POST /api/uploads，并用 XMLHttpRequest upload.onprogress 上报进度，不做分片与断点续传。

## 四、审核预处理合并

MChecker 后端 agent_backend/main.py 使用 ffmpeg 从视频 URL 抽帧并做多模态内容审核。PulseFrame 的设计明确 Agent 初审随后续工作流接入，因此本文只登记能力，不改变当前的人工审核模型。接入时复用 review_task 与 review_decision_log，operator_type 取 AGENT。

## 五、冲突与取舍

- douyin 发布页没有真实提交接口，不能直接作为链路实现，只作为前端交互参考。
- MChecker 审核消耗视频但不产生发布，只提供抽帧与分析的实现参考。
- GCFeed 作为后端工程结构参考，不直接作为 PulseFrame 代码基础，PulseFrame 的需求、数据模型与接口从零推导。
- 媒体存储、视频状态枚举、审核任务结构均以 PulseFrame 设计文档为准，不采用三个参考项目的字段命名。
