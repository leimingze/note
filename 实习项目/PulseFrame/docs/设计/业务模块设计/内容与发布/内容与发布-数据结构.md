# MySQL 表

流程说明见 [内容与发布](内容与发布.md)。本模块只有两张表：`video` 保存视频与发布状态，`review_task` 保存送审记录并兼作待投递队列。

每个字段与取值的逐项设计理由见 [内容与发布-字段设计说明](内容与发布-字段设计说明.md)。

## 通用约定

```text
使用 MySQL 8.0、InnoDB，字符集 utf8mb4。
author_id 引用 users.id，使用 CHAR(36) CHARACTER SET ascii COLLATE ascii_bin。
所有 DATETIME(3) 由应用按 UTC 写入；未注明"可空"的字段均为 NOT NULL。
不建物理外键：关联关系由应用在同一事务内维护，避免写入时的额外锁检查，也不妨碍以后分库。
状态与时间字段的组合规则由应用层的状态转换函数统一维护，不用 CHECK 约束表达。
```

不使用 CHECK 和外键的原因：状态规则会随业务变化，写在一个 Go 函数里改起来比改约束简单，单测也能覆盖每一条状态边；上一版用 12 条 CHECK 约束状态组合，结果每条写语句都要记住"同时清哪个字段"，写路径反而更容易出错。

## 1. video：视频表（17 字段）

| 字段 | 类型 | 约束 | 用途 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | 主键，自增 | 视频 ID，对象键也以它为前缀 |
| author_id | CHAR(36) ascii_bin | 无默认 | 作者 |
| title | VARCHAR(64) | 默认 '' | 标题 |
| description | VARCHAR(1000) | 默认 '' | 简介与话题文本 |
| status | TINYINT UNSIGNED | 默认 0 | 0上传中/1草稿/2待审核/3已驳回/4已发布/5已隐藏/6已下架 |
| media_key | VARCHAR(255) | 默认 '' | 正式视频对象键 `videos/{id}/media.mp4`，确认上传后写入 |
| cover_key | VARCHAR(255) | 默认 '' | 正式封面对象键 `videos/{id}/cover_{n}.{ext}` |
| duration_ms | INT UNSIGNED | 默认 0 | 时长，确认上传时由探测结果写入，之后不变 |
| width | SMALLINT UNSIGNED | 默认 0 | 宽度，客户端布局占位 |
| height | SMALLINT UNSIGNED | 默认 0 | 高度 |
| size_bytes | BIGINT UNSIGNED | 默认 0 | 文件大小 |
| review_round | INT UNSIGNED | 默认 0 | 当前审核轮次，每次提交加 1，回调据此判断新旧 |
| reject_reason | VARCHAR(200) | 默认 '' | 最近一次驳回原因，重新提交时清空 |
| offline_reason | VARCHAR(200) | 默认 '' | 下架原因，作者可见 |
| published_at | DATETIME(3) | 可空 | 首次审核通过时间，公开列表排序依据 |
| deleted_at | DATETIME(3) | 可空 | 删除时间，非空表示在回收站 |
| created_at | DATETIME(3) | 无默认 | 创建时间，我的作品排序依据 |

`submitted_at`、`updated_at` 不单独建列：提交时间就是对应 `review_task.created_at`，审核时长统计从任务表计算；修改时间没有读取方。

```text
索引：
- idx_video_author_public (author_id, status, published_at, id)
    他人公开作品列表：WHERE author_id=? AND status=4 AND deleted_at IS NULL
    ORDER BY published_at DESC, id DESC
    deleted_at 不放进索引：已删除的视频通常很少，回表过滤的代价可以忽略
- idx_video_author_created (author_id, deleted_at, created_at, id)
    我的作品与回收站：WHERE author_id=? AND deleted_at IS NULL（或 IS NOT NULL）ORDER BY created_at DESC
    按状态过滤时在该索引上回表过滤，单个作者的视频数量有限，不再为每种状态建索引
- idx_video_cleanup (deleted_at)
    回收站超期清理
- idx_video_created (status, created_at)
    清理 1 天前仍在上传中的记录
```

列表查询先只取 `id`（公开列表在 `idx_video_author_public` 上覆盖），再按 ID 批量读详情缓存，因此索引只负责过滤和排序，展示字段不需要放进索引。

为什么不建计数字段或计数表：点赞、评论、收藏、播放数的写入频率比视频本身高几个数量级，归互动模块管理。和视频行放在一起，每次点赞都会更新视频行并删除详情缓存，缓存命中率会大幅下降。

## 2. review_task：送审记录表（10 字段）

一轮审核一行。`status IN (1,2)` 的行是投递 worker 的待处理队列。

| 字段 | 类型 | 约束 | 用途 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | 主键，自增 | 任务 ID，即投递给审核服务的 task_id，审核服务以它去重 |
| video_id | BIGINT UNSIGNED | 无默认 | 关联视频 |
| review_round | INT UNSIGNED | 无默认 | 第几轮审核，对应提交时的 `video.review_round` |
| status | TINYINT UNSIGNED | 默认 1 | 1待投递/2审核中/3通过/4驳回/5投递失败/6已取消 |
| reason | VARCHAR(200) | 默认 '' | 驳回原因 |
| attempt_count | SMALLINT UNSIGNED | 默认 0 | 领取次数，达到 5 次后置为投递失败 |
| next_attempt_at | DATETIME(3) | 无默认 | 下次可被领取的时间：待投递时是重试时间，审核中时是对账时间 |
| created_at | DATETIME(3) | 无默认 | 提交时间，用于审核时长统计 |
| decided_at | DATETIME(3) | 可空 | 出结论时间 |
| updated_at | DATETIME(3) | 无默认 | 最近修改时间，排查问题用 |

```text
索引：
- uk_review_video_round (video_id, review_round)：同一视频同一轮只有一个任务，也用于按视频查历史
- idx_review_due (status, next_attempt_at)：worker 领取 WHERE status IN (1,2) AND next_attempt_at <= now
```

`next_attempt_at` 必须在插入时写入当前时间。留空时 `NULL <= now` 不成立，新任务永远不会被领取。

状态转换：

```text
1 待投递 → 2 审核中     投递成功，条件 WHERE status=1
1 待投递 → 5 投递失败   attempt_count 达到 5
1 待投递 → 6 已取消     作者撤回或删除
1/2      → 3 通过/4 驳回 回调或对账拿到结论，条件 WHERE status IN (1,2)
```

`status=1` 也允许直接写结论：审核服务可能在 worker 把任务改为审核中之前就完成回调。回调按 `task_id` 即主键定位任务。已取消的任务收到迟到回调时直接返回 200，不再记录结论。

# Redis

## 通用约定

```text
key 中的 {...} 替换为业务标识。
Redis 只存可丢失的数据：缓存与限流计数。Redis 数据全部丢失时，业务只会变慢或暂时不限流，不会出错。
```

## 1. 视频详情缓存

类型：String（JSON）。

key：`video:{videoId}`，TTL 600 秒 + 0~60 秒随机。不存在的视频缓存空值 `{}`，TTL 60 秒。

| JSON 字段 | 来源 |
| --- | --- |
| id、author_id、title、description | video 表 |
| status、deleted_at、published_at、created_at | video 表，接口层据此判断可见性 |
| media_key、cover_key | video 表，接口层签发地址时使用 |
| duration_ms、width、height | video 表 |
| reject_reason、offline_reason | video 表，只返回给作者 |

```text
读取：单条 GET；批量 MGET，未命中的 ID 一次 IN 查询后用 pipeline SET 回填
写入：修改 video 的操作在事务提交后 DEL video:{videoId}；
      视频变为公开（审核通过、恢复公开）时改为用最新数据 SET，即发布预热
不存签名地址：签名有时效且只对可见的查看者签发
```

## 2. 上传频率限制

类型：String（计数器）。

```text
key：rl:upload:h:{userId}，TTL 3600 秒，上限 10
key：rl:upload:d:{userId}，TTL 86400 秒，上限 50
每次创建视频时 INCR；值为 1 时设置 EXPIRE（两条命令放在一个 Lua 脚本里，避免只 INCR 未设过期）
超过上限返回 429，Retry-After 取 key 的剩余 TTL
```

单个文件大小由预签名策略的 `content-length-range` 限制，每天最多 50 个文件，因此不再单独统计字节配额。

# 对象存储

```text
桶：一个私有桶，禁止匿名读；CDN 回源访问该桶并开启 URL 签名鉴权

key 规则：
  upload/{videoId}/media.mp4          客户端直传的临时对象
  upload/{videoId}/cover.{jpg|png}    同上
  videos/{videoId}/media.mp4          确认上传后由服务端复制的正式对象
  videos/{videoId}/cover_{n}.{ext}    正式封面，n 从当前 cover_key 解析，换封面时加 1
  offline/{videoId}/...               下架后移入，保留取证，回收站超期时删除

生命周期规则：upload/ 前缀下的对象 1 天后自动删除
```

一个视频的所有对象都在 `{videoId}` 前缀下，删除视频时按前缀删除即可，不存在多个视频共享同一个对象的情况。
