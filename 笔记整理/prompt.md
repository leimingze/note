# 技术笔记整理

请把提供的技术笔记整理成一份完整、易懂、兼容 Obsidian Mappy 的 Markdown 笔记。读者会通过 Edit body and links 直接阅读未经渲染的正文，因此正文要像自然讲解一样，即使看到原始文本也能顺着读懂。

## 输入

原始笔记：{笔记}

业务场景：{场景}（可选，未提供时选择贴合主题的具体例子）

## 内容与表达

- 按理解顺序组织内容：先解释必要概念，再说明机制、完整过程和应用。尽量用同一个例子贯穿相关章节，保持人物、对象、数值和先后顺序一致。
- 每个节点都在当前正文讲清楚结论、原因、过程和结果。父节点概括完整过程，子节点补充机制；理解当前内容所需的前提当场解释，让读者无需反复进入子节点查定义。
- 使用口语化的短句和自然段，说明谁做了什么、为什么这样做、最后发生什么。术语首次使用时解释含义；单独阅读某个节点需要的背景，也在该节点简短交代。
- 保留原文全部知识点、必要机制、关键参数、数值、例子和适用条件。SQL、命令、参数及公式按需使用普通文本写出，并解释含义。内容完整，表达简洁，避免重复。
- 补齐原文中能够确认的待补内容，纠正错误或过时表述。影响结论的版本、配置和例外条件在相关正文说明；无法确认时，直接说明缺少什么信息，不编造结论。

## Mappy 格式

- 文件以 YAML 属性块开始，包含 mappy: true。用一个二级标题表示主题，三级标题表示主要章节，四级标题表示小节，按基础到深入的顺序排列。标题简短，直接说明主题。
- 标题下的正文只用普通文本和空行分段。比较内容分段说明，流程用“首先、接着、最后”等自然语言连接；正文不使用表格、加粗、反引号、代码围栏、引用块或列表标记。
- 原文有图片时，保留全部原图引用，集中放在文末的“配图”章节，每张图使用独立的小节标题。正文自身应讲解完整，不依赖图片才能理解。
- 图片使用标准 Markdown 图片语法，按输出文件位置计算相对路径，直接引用原文件。检查路径有效，不复制或移动图片，不新建图片目录或符号链接，不编造图片。

## 输出

只输出一份完整笔记，全文不包裹在代码围栏中，不附修改说明或检查清单。交付前检查知识是否完整、术语是否当场解释、正文能否直接口述、标题层级和图片引用是否正确。

## 格式示例

```markdown
---
mappy: true
---
## MySQL 日志

假设用户把姓名从 xiaohong 改成 xiaolin。修改可能被取消，数据库也可能突然断电，所以需要记录撤销和恢复所需的信息。undo 保存撤销修改所需的信息。redo 记录数据页的修改，数据页就是数据库按块读写数据时使用的单位。binlog 记录供副本同步及历史恢复使用的变更事件。

### undo：撤销修改，也提供历史版本

事务是一组需要一起确认或一起撤销的操作。undo 会保留撤销这次改名所需的信息。事务取消时，数据库用它恢复旧姓名；查询需要历史版本时，也可以用它重建旧姓名。回滚会撤销当前修改，查询只是读取重建出的旧记录，不会把当前姓名改回去。

#### 回滚怎样恢复旧姓名

事务是一组需要一起确认或一起撤销的操作。把 xiaohong 改成 xiaolin 时，InnoDB 会保留旧姓名和相关撤销信息。InnoDB 是负责保存和读写表数据的存储引擎。随后执行 ROLLBACK，也就是取消事务，引擎就根据这些信息恢复原来的记录。如果事务做了多次修改，回滚会按相反的次序逐项撤销。
```
