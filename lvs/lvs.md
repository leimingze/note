# 什么是lvs
LVS （ Linux Virtual Server, Linux虚拟服务器）是一个虚拟的服务器集群系统，其负责决定将用户请求转发到哪台Nginx服务器。

由于LVS基于OSI参考模型的网络层，免去了请求到应用层的层层解析工作，而且LVS工作于操作系统层面，所以LVS相比于Nginx有更高的性能。
LVS用于网络接入层时也被称为四层负载均衡器。既然LVS四层负载均衡器做的主要工作是转发，那么就需要
讨论一下转发模式。目前，LVS主要有4种转发模式：NAT模式、FULLNAT模式、TUN
模式、DR模式
# lvs和nginx区别
Nginx是基于OSI参考模型的**第七层（应用层）协议**开发的。
nginx采用了**异步转发**形式。Nginx在保持客户端连接的同时新建一个与业务服务器的连接，等待业务服务器返回响应数据，然后再将响应数据返回给客户端。
Nginx选择异步转发的好处是可以进行失败转移（failover）,如果与某台业务服务器的连接发生故障，那么就可以换另一个连接，提高了服务的稳定性。Nginx主要强调的是“代理”。

LVS是基于OSI参考模型的**第四层（网络层）协议**开发的，采用了**同步转发**形式。 当LVS监听到有客户端请求到来时，会直接通过修改数据包的地址信息将流量转发到下游服务器，让下游服务器与客户端直接连接。LVS主要强调的是“转发”。

```text
                     ▼              ▼              ▼
                  RS1(真实服务器)  RS2(真实服务器)  RS3(真实服务器)

```
# NAT 模式
NAT模式是指通过修改请求报文的目标IP地址和目标端口号实现DS到某个RS的请求转发。在此模式下，网络报文的请求与响应都要经过DS的处理，DS是RS的网关

```text
入向：CIP → VIP
DS 改为：CIP → RIP        ← 只改了目的 IP

回向：RIP → CIP
RS 发现目的 IP 是 CIP（外网 IP），自己没有直连路由
  → 必须走默认网关 → 网关指向 DS
  → DS 收到后，只改源 IP → VIP        ← 只改了源 IP
```

**nat模式要满足以下条件**：DS需要两块网卡，其中一块网卡面向公网提供VIP,另一块网卡面向内部网络提供 DIP。DS需要和所有的RS处于同一个局域网内，并将DS设置为局域网的网关，否则RS的响应数据将无法传输到DS。

**缺点**：客户端请求和服务器响应都会经过DS重写，而服务器响应数据的长度一般远大于客户端请求的长度，响应数据会对DS造成网络带宽压力。

# FULLNAT 模式
不要求DS与RS处于同一个局域网内且作为网关。DS在NAT模式的基础上又做了一次源IP地址转化，这样一来，当RS返回响应数据时，根据IP地址即可将其正常路由到DS,而不需要强行指定DS为网关。

**缺点**：请求到达RS后会丢失客户端IP地址。

```text
入向：CIP → VIP
DS 改为：DIP → RIP        ← 同时改了源IP和目标IP！
         （伪装成自己发出的）

回向：RIP → DIP
DS 收到后改为：VIP → CIP  ← 再改回来
```

# TUN （IP隧道）模式
DS通过IP隧道加密技术将请求报文封装到一个新的数据包中，并选择一个RS的IP地址作为新数据包的目的IP地址，然后将它发送到对应的RS RS基于IP隧道解密技术解析出原数据包的内容，查看RS本地是否绑定了原数据包的目的IP地址，如果是，则处理请求并将响应结果通过网关返回给客户端

```text
原始包（不动）：
  ┌──────────────────────┐
  │ CIP → VIP            │  ← 原包原封不动
  │ TCP / 数据           │
  └──────────────────────┘

DS 在外面套一层新 IP 头：
  ┌─────────────────────────────────┐
  │ DIP → RIP                       │  ← 新外层头
  │ ┌──────────────────────┐        │
  │ │ CIP → VIP            │        │  ← 原包整个塞进去
  │ │ TCP / 数据           │        │
  │ └──────────────────────┘        │
  └─────────────────────────────────┘

入向：
CIP → VIP
DS 收到后：
  外层封装：DIP → RIP        ← 新加了一层 IP 头，目的 IP 是 RIP
  内层保持：CIP → VIP        ← 原包不动，裹在里面

回向：
VIP → CIP
RS 拆掉外层隧道头，取出内层包：CIP → VIP
RS 发现目的 IP 是 CIP（外网 IP），不在本地隧道
  → 查路由表 → 走默认网关（出口路由器，不是 DS）
  → 直接发包给网关，不经过 DS
```

# DR 模式
```text
入向：
CIP → VIP
DS 收到后：
  只改目的 MAC → RS_MAC        ← 不改 IP，只改二层

回向：
VIP → CIP
RS 发现目的 IP 是 CIP（外网 IP），不在本地网段
  → 查路由表 → 走默认网关（出口路由器，不是 DS）
  → 直接发给网关，不经过 DS
```

# LVS 四种转发模式对比

| 模式 | DS 做了什么 | 包怎么到 RS | 为什么能工作（含 VIP / 校验逻辑） | 网关相关 | 优势 | 劣势 / 注意点 |
|------|------------|-------------|--------------------------------|----------|------|--------------|
| **NAT** | 入向改目的 IP：VIP → RIP；回包反向改源 IP：RIP → VIP | 三层路由转发 | RS 看到源 IP 是 CIP（客户端真实 IP），不需要认领 VIP，内核直接交给应用 | **RS 默认网关必须指向 DS**。因为回包源 IP 是 RIP，客户端不认 RIP，必须让 DS 把 RIP 改回 VIP 后发出去，所以回包必须经过 DS，网关就是强制引流回 DS 的那道关卡 | RS 零配置；部署简单 | DS 双向参与，性能瓶颈；RS 网关被绑死在 DS 上 |
| **FULLNAT** | 入向同时改源和目的：CIP→DIP，VIP→RIP；回包反向全改 | 三层路由转发 | RS 看到源 IP 是 DIP（DS 的 IP），不感知 VIP，不需要认领 VIP，内核直接交给应用 | **RS 默认网关可以指向任何路由器**。因为入向就把源 IP 换成了 DIP，回包目的 IP 是 DIP（DS 的 IP），三层路由天然可达 DS，不依赖网关硬拐回 DS | 网络环境最灵活，RS 网关不用动 DS，部署自由度最高 | CIP 被 DIP 覆盖，对 RS 不可见（需 TOA/XFF 等机制透传）；DS 双向全量处理，仍有性能开销 |
| **TUN** | IP 封装：外层 DIP→RIP，内层 CIP→VIP 原样裹入 | 三层路由送 RIP，RS 内核 ipip 解封装 | 解封后内层目的 IP=VIP，RS lo 口必须配 VIP 内核才认领（否则静默丢弃）；需 ARP 抑制 + 关 rp_filter | 同 FULLNAT，**RS 网关随便指**，回包 VIP→CIP 直接走默认网关出，不经过 DS | 可跨三层/跨机房；回程不经 DS，性能好 | RS 需 ipip 模块 + lo 配 VIP；可能出现"外层 RIP 对但内层 VIP 错"导致内核丢包 |
| **DR** | 只改帧头目的 MAC → RS_MAC，IP 头完全不动 | 同二层交换机直送（靠 MAC 寻址） | RS 拆帧后看目的 IP=VIP，lo 口必须配 VIP 才认领（否则丢弃）；需 ARP 抑制防抢答 VIP | **RS 网关随便指**，回包 VIP→CIP 直接走出口路由器，不经过 DS | 性能最高，零封装零改 IP，包大小不变 | DS/RS 必须同广播域；RS 需 lo 配 VIP；同样存在"MAC 对但 VIP 错"丢包 |

## 网关区别总结（NAT vs FULLNAT）

| | NAT | FULLNAT |
|--|-----|---------|
| RS 看到的源 IP | CIP（客户端真实 IP） | DIP（DS 的 IP） |
| 回包目的 IP | CIP（外网 IP） | DIP（DS 的 IP，同网段） |
| 回包怎么到 DS | **必须靠网关指向 DS 硬拐回来** | 三层路由自然可达（DIP 就是 DS） |
| RS 网关要求 | **必须指向 DS**（强制引流，网关兼职"保安"） | **可以指向任何路由器**（网关回归正常出口角色） |
| 本质原因 | 回包源 IP 是 RIP，客户端不认，只有 DS 能改回 VIP，所以回包必须经过 DS | 入向就替客户端"认了"（CIP→DIP），回包天然发给 DS，不需要网关强制引流 |

> **一句话记忆**：NAT 靠网关硬拐回 DS 改地址；FULLNAT 入向就改好，回包自动回 DS，网关不用管。
