# Agent 评估与工程化面试学习路线

本目录用于从零学习 AI Agent 的评估、测试与生产工程，并沉淀一套可执行、
可复现、可持续迭代的方法。最终目标是应对 Agent 工程相关面试，而不只是读完资料。

学习闭环如下：

```text
理解测试基本概念
→ 认识单 Agent、多 Agent 的组成与失败模式
→ 设计离线评估、自动化测试与安全测试
→ 建立线上观测、成本和延迟治理
→ 打通回归测试、发布门禁与线上反馈
→ 用工程案例形成有证据、有取舍的面试回答
```

## 1. 学习目标

完成本路线后，面对 Agent 评估、测试、上线监控、安全、成本与延迟、
多 Agent 协作六类面试问题，应能先澄清场景，再给出系统方案，而不是罗列术语。

### 1.1 统一答题框架

每个问题都按“目标—风险—方案—指标—闭环—取舍”展开：

1. **目标与边界**：业务成功是什么，Agent 有哪些工具、权限、环境和质量约束。
2. **风险与失败模式**：结果、轨迹、状态、依赖和人为因素可能怎样失败。
3. **工程方案**：数据、组件、流程、评分器、护栏或协作架构如何设计。
4. **指标与证据**：用哪些质量、稳定性、安全、成本和延迟指标证明有效。
5. **上线闭环**：如何回归、灰度、告警、定位、回滚，并把 Bad Case 纳入评测集。
6. **取舍与演进**：解释质量、风险、复杂度、成本和速度之间的选择及适用条件。

表达标准：清晰是先给结论并定义边界；有条理是沿统一框架展开；
有深度是能讲失败模式、指标依据、工程取舍和方案失效条件，并用案例支撑。

### 1.2 六类核心能力

| 面试主题 | 学完后应能回答的核心问题 |
| --- | --- |
| Agent 评估 | 如何从业务目标定义任务、Golden Set、Outcome/Trace 指标和评分器，并判断版本差异是否可信 |
| Agent 测试 | 如何分层测试概率性系统，覆盖正常、边界、异常、对抗、状态迁移和非确定性回归 |
| 上线监控 | 如何采集 Trace、日志、指标与反馈，定义 SLI/SLO、告警、归因、灰度和回滚闭环 |
| 安全 | 如何围绕提示注入、越权工具调用、数据泄露和危险副作用做威胁建模、最小权限与审计 |
| 成本与延迟 | 如何拆解 Token、模型、工具和重试开销，分析端到端及 P95/P99 延迟，并在质量约束下优化 |
| 多 Agent 协作 | 何时值得从单 Agent 升级，如何选择流水线、编排器或去中心化协作，并处理通信、共享状态、终止、归因和额外开销 |

回答不能停留在概念定义。每个主题至少要能给出一个具体场景、一套可落地方案、
关键指标、主要失败模式和一个明确的工程取舍。

## 2. 先建立统一认识

Agent 测评不是“让模型回答几道题并算平均分”。一次 Agent 执行至少要观察四个层次：

| 层次 | 核心问题 | 常见检查项 |
| --- | --- | --- |
| 输入与状态 | 测试条件是否明确、可复现 | 用户输入、初始状态、权限、上下文、环境 |
| Trace / Trajectory | 执行过程是否正确 | 工具选择、参数、调用顺序、重试、状态变化 |
| Outcome | 任务是否真正完成 | 最终答案、文件、数据库状态、外部副作用 |
| 系统质量 | 是否能稳定用于生产 | 多次运行成功率、延迟、成本、安全、体验 |

最终答案正确但过程错误，仍可能是假阳性。例如 Agent 没有查询订单状态，
却碰巧给出了正确退款结论。Agent 测评因此必须同时覆盖 Response、Trace 和 Outcome。

## 3. 最小前置知识

不需要先系统学完所有计算机基础。测试能力是主线，其他知识只在 Demo、项目或岗位要求用到时补齐：

- **主线**：测试流程、测试类型、用例设计、缺陷管理、UI 与接口自动化、抓包、性能测试、数据与中间件验证。
- **按需补齐**：语言、网络、数据结构、算法与复杂 SQL，不作为进入 Agent 学习的前置门槛。
- **项目必需的最低基础**：能修改现有测试脚本、理解 HTTP 请求，并用基础 SQL 校验 MySQL 数据；缺什么补什么。
- **LLM 基础**：Prompt、Token、Temperature、Embedding、RAG、幻觉。
- **Agent 基础**：Tool、Planning、Memory、Reflection、Guardrail、Human-in-the-Loop。

遇到陌生术语时先记录一句话定义，不要为了补全理论而中断整条学习路线。

## 4. 推荐学习顺序

建议按阶段学习，不按资料体量从头到尾通读。每个阶段都包含学习重点、
指定资料、阶段产出和面试验收；完成产出并能回答验收问题后，再进入下一阶段。

### 三遍学习法

所有模块都采用同一种节奏：

1. **简单学习**：只掌握完成第一个 Demo 所需的核心概念，不在入门阶段追求知识穷举。
2. **Demo 复现**：运行一个范围明确的小例子，同时观察成功路径和至少一种真实失败。
3. **项目强化**：把 Demo 中的能力接入同一个综合项目，补齐异常、边界、数据、性能和工程规范。

第一遍解决“知道是什么”，第二遍解决“能够做出来”，第三遍解决“能够在真实项目中设计、排错和取舍”。
面试答案以第三遍形成的工程证据为主，不能只复述第一遍的概念。

工业案例和 Benchmark 不单独占用阶段：腾讯、阿里案例用于学习离线评估和测试，
美团案例用于学习线上观测，VitaBench 用于练习 Benchmark 审计。

| 阶段 | 重点 | 主要资料 | 阶段产出 |
| --- | --- | --- | --- |
| 0 | 软件测试主线与按需基础 | 测试设计、自动化、工具、数据与中间件 | 一个 Web/API 测试项目 |
| 1 | Agent 架构与失败模式 | 两本 Agent 资料的基础章节 | 执行链路图和失败模式表 |
| 2 | 离线评估与统计判断 | AI Engineering、行业评测、VitaBench、Anthropic Agent 评测 | Golden Set 和版本对比报告 |
| 3 | 自动化测试与发布门禁 | 测试指南、行业实践 | 可执行回归集和门禁规则 |
| 4 | 上线监控与故障处理 | 评估监控章节、美团实践 | 可观测方案和事故演练 |
| 5 | 安全测试与权限治理 | 安全护栏、人机协同 | 威胁模型和红队用例 |
| 6 | 成本、延迟与性能优化 | 资源优化、部署实践 | 性能剖析和优化对比 |
| 7 | 多 Agent 协作与测试 | 多智能体、A2A、并行执行 | 单 Agent 与多 Agent 对照实验 |
| 8 | 综合项目与面试演练 | 前述全部材料 | 生产方案和六类答题提纲 |

### 阶段 0：软件测试主线与按需基础

阶段 0 分为主线和按需补齐两部分。优先沿主线完成项目；非主线模块可以并行学习，
也可以等 Demo 或项目遇到具体问题时再补，不作为阶段完成的阻塞条件。

| 顺序 | 模块 | 定位 | 学习范围 | 小 Demo |
| --- | --- | --- | --- | --- |
| 0.1 | 语言 | 按需补齐 | Python 优先：语法、函数、面向对象、异常、文件、JSON、HTTP 请求、pytest；Java：集合、面向对象、Maven、TestNG | 读取测试数据、请求接口并完成断言 |
| 0.2 | 网络 | 按需补齐 | TCP/IP、DNS、HTTP/HTTPS、REST、状态码、Header、Cookie、Session、Token、代理、超时和重试 | 拆解一次登录请求及失败响应 |
| 0.3 | 数据结构 | 按需补齐 | 数组、链表、栈、队列、哈希表、树、堆、排序、查找和时间复杂度 | 用哈希表统计结果，用队列模拟任务执行 |
| 0.4 | 测试八股与用例设计 | 主线 | 测试流程与分类、缺陷管理、测试层级、等价类、边界值、决策表、场景法和状态迁移 | 为登录或订单功能编写 10 条用例 |
| 0.5 | 自动化测试 | 主线 | UI 使用 Selenium；接口使用 Python `requests + pytest`，同时理解 Java `REST Assured + TestNG` | 自动执行一个 UI 流程和一组接口用例 |
| 0.6 | 测试工具 | 主线 | Postman 做接口调试与集合执行，Charles 做 HTTP/HTTPS 抓包，JMeter 做接口压测 | 完成一次接口集合、抓包分析和阶梯压测 |
| 0.7 | 数据与中间件 | 主线 | MySQL、项目所需基础 SQL、Redis、RabbitMQ 或 RocketMQ | 校验数据库、缓存和消息最终状态 |
| 0.8 | 算法与复杂 SQL | 按需补齐 | 常见算法模式；连接、聚合、子查询、窗口函数、索引和执行计划 | 按目标岗位练习算法与 SQL 题 |

- **技术取舍**：消息队列优先学习 RabbitMQ 或 RocketMQ，第一轮不把 Kafka 作为重点；先掌握消息投递、确认、重试、幂等、顺序和积压，再按岗位需要补 Kafka。
- **指定资料**：[软件测试基础：一个功能从需求到上线](学习指南/01-软件测试基础.md)和[软件测试度量与发布判断](学习指南/02-软件测试度量与发布判断.md)，先沿 0.4 → 0.5 → 0.6 → 0.7 学习，其他模块按实际缺口补充。
- **阶段产出**：选择一个 Web/API 系统，提交测试用例、Selenium 脚本、pytest 或 TestNG 接口回归、Postman 集合、Charles 抓包证据、JMeter 报告、SQL 校验及缓存或消息队列验证记录。
- **面试验收**：能讲清请求从客户端到服务端、数据库、缓存和消息队列的链路，并能选择合适的测试层、工具、断言和数据校验方式。

### 阶段 1：Agent 架构与失败模式

- **学习重点**：模型、提示词、RAG、工具、记忆、规划、循环、权限和运行环境如何组成执行链路。
- **指定资料**：[Agent 基础](原始资料/ai-agents-in-action/cn-book/1.AI智能体的崛起.md)、[核心组件](原始资料/ai-agents-in-action/cn-book/2.核心组件.md)、[工具使用](原始资料/agentic-design-patterns/bilingual/Chapter%205_%20Tool%20Use.md)、[规划](原始资料/agentic-design-patterns/bilingual/Chapter%206_%20Planning.md)、[记忆](原始资料/agentic-design-patterns/bilingual/Chapter%208_%20Memory%20Management.md)和[异常恢复](原始资料/agentic-design-patterns/bilingual/Chapter%2012_%20Exception%20Handling%20and%20Recovery.md)。
- **阶段产出**：画出一个 Agent 的执行链路，为每个组件列出至少 2 种可观察失败模式及对应证据。
- **面试验收**：能从 Outcome、Trace、状态和系统质量四层解释为什么 Agent 不能只测最终答案。

### 阶段 2：离线评估与统计判断

- **学习重点**：业务成功标准、数据分层、Golden Set、确定性评分、LLM-as-a-Judge、人工校准、能力与回归评测转化、pass@k 与 pass^k、重复运行和版本差异判断。
- **指定资料**：[AI Engineering](原始资料/ai-engineering/ToC.md)第 3、4、6、8 章、[Agent 评估与反馈](原始资料/ai-agents-in-action/cn-book/7.通过评估与反馈构建稳健的智能体.md)、[腾讯实践](原始资料/tencent-agent-skill/tencent-agent-skill.html)、[阿里实践](原始资料/alibaba-agent-eval/alibaba-agent-eval.html)、[Anthropic：Agent 评测入门](原始资料/anthropic-agent-evals/anthropic-agent-evals.html)和[VitaBench](原始资料/vitabench/vitabench.pdf)。
- **阶段产出**：建立 20 至 50 条 Golden Set，校准至少两类评分器，多次运行基线版与候选版并输出分层对比报告。
- **面试验收**：能解释数据如何构建、评分器为何可信、波动如何处理，以及 Benchmark 结论为何不能直接代表业务效果。

### 阶段 3：自动化测试与发布门禁

- **学习重点**：把阶段 0 的自动化能力迁移到 Agent，覆盖单元、组件、契约、集成、端到端测试，以及 Mock、Sandbox、故障注入、概率性回归、Flaky Case 和 CI 门禁。
- **指定资料**：[软件测试基础](学习指南/01-软件测试基础.md)、[异常恢复](原始资料/agentic-design-patterns/bilingual/Chapter%2012_%20Exception%20Handling%20and%20Recovery.md)、腾讯、阿里与 Anthropic 实践中的回归方法。
- **阶段产出**：把阶段 2 的核心用例转成可重复执行的回归集，定义分层断言、重复次数、失败证据和发布阻断规则。
- **面试验收**：能设计模型、Prompt、工具或知识库变更后的测试范围，并解释如何降低回归成本而不隐藏失败。

### 阶段 4：上线监控与故障处理

- **学习重点**：Trace、日志、指标、反馈的关联，SLI/SLO、告警、灰度、回滚、质量代理指标、漂移和 Bad Case 回流。
- **指定资料**：[评估与监控](原始资料/agentic-design-patterns/bilingual/Chapter%2019_%20Evaluation%20and%20Monitoring.md)、[生产实践](原始资料/ai-agents-in-action/cn-book/11.构建智能体系统的实用技巧.md)和[美团实践](原始资料/meituan-agent-eval/meituan-agent-eval.html)。
- **阶段产出**：为同一 Agent 定义 Trace 字段、核心 SLI/SLO、告警条件、排障路径、灰度和回滚方案，并完成一次事故演练。
- **面试验收**：能区分模型退化、工具故障、数据漂移和流量变化，并说明线上无法获得标准答案时如何监控质量。

### 阶段 5：安全测试与权限治理

- **学习重点**：提示注入、间接注入、工具与 MCP 供应链、越权调用、数据泄露、记忆污染、危险副作用、最小权限、审批和审计。
- **指定资料**：[安全护栏](原始资料/agentic-design-patterns/bilingual/Chapter%2018_%20Guardrails_Safety%20Patterns.md)、[人机协同](原始资料/agentic-design-patterns/bilingual/Chapter%2013_%20Human-in-the-Loop.md)和[部署 Agent](原始资料/ai-agents-in-action/cn-book/8.部署智能体与智能体系统.md)。
- **阶段产出**：从输入、上下文、工具、记忆和输出五层完成威胁模型，设计至少 10 条红队用例和高风险操作审批边界。
- **面试验收**：能解释护栏为何不能只靠 Prompt，以及权限隔离、沙箱、人工审批和审计如何组合。

### 阶段 6：成本、延迟与性能优化

- **学习重点**：Token、模型、工具、重试和多 Agent 开销，端到端关键路径，P50/P95/P99，以及缓存、路由、并行和上下文压缩。
- **指定资料**：[资源感知优化](原始资料/agentic-design-patterns/bilingual/Chapter%2016_%20Resource-Aware%20Optimization.md)、[并行执行](原始资料/agentic-design-patterns/bilingual/Chapter%203_%20Parallelization.md)和[生产实践](原始资料/ai-agents-in-action/cn-book/11.构建智能体系统的实用技巧.md)。
- **阶段产出**：对至少 10 次执行拆解成本与延迟，定位主要瓶颈，实施一项优化并比较质量、稳定性、成本和延迟变化。
- **面试验收**：能提出带质量约束的优化方案，并说明哪些并行、缓存或模型降级会破坏正确性。

### 阶段 7：多 Agent 协作与测试

- **学习重点**：何时使用多 Agent，流水线、编排器和去中心化协作，通信契约、共享状态、幂等、终止、局部失败和归因。
- **指定资料**：[多 Agent 架构](原始资料/ai-agents-in-action/cn-book/4.架构与构建多智能体系统.md)、[多智能体协作](原始资料/agentic-design-patterns/bilingual/Chapter%207_%20Multi-Agent%20Collaboration.md)、[A2A](原始资料/agentic-design-patterns/bilingual/Chapter%2015_%20Inter-Agent%20Communication%20(A2A).md)和[并行执行](原始资料/agentic-design-patterns/bilingual/Chapter%203_%20Parallelization.md)。
- **阶段产出**：为同一任务设计单 Agent 与多 Agent 方案，注入通信失败、重复执行、超时和分工冲突，比较质量、稳定性、成本、延迟和可诊断性。
- **面试验收**：能说明多 Agent 带来的真实收益、额外成本、失败归因方法，以及何时应退回单 Agent 或确定性工作流。

### 阶段 8：综合项目与面试演练

- **学习重点**：把评估、测试、监控、安全、性能和多 Agent 串成从需求到上线的完整闭环。
- **指定资料**：回看前述产出和工业案例，只补充影响方案决策的内容，不再横向扩充资料。
- **阶段产出**：完成一份生产级 Agent 测试方案，包含架构、失败模型、评测集、回归门禁、线上观测、安全控制、性能预算和版本对比。
- **面试验收**：为六类主题分别准备 2 分钟概念回答、5 分钟系统方案、一个工程案例、三个追问和一个方案失效条件，并完成至少两轮模拟面试。

## 5. 三类评分器

| 评分器 | 适用内容 | 优点 | 主要风险 |
| --- | --- | --- | --- |
| 确定性评分器 | 文件、字段、工具、参数、状态、禁止动作 | 快、便宜、稳定、可复现 | 只能覆盖已明确编码的规则 |
| LLM-as-a-Judge | 相关性、完整性、表达质量、策略合理性 | 能处理开放式自然语言 | 模型偏差、位置偏差、分数抖动 |
| 人工评审 | 标准制定、困难样本、高风险决策 | 最接近业务目标 | 成本高、速度慢、评审者可能不一致 |

使用顺序：能用代码可靠判断的内容优先使用确定性评分；开放式语义问题再使用 LLM；人工负责制定标准、校准评委和审查高风险样本。

## 6. 核心术语

| 术语 | 本目录中的含义 |
| --- | --- |
| Case | 一条包含输入、状态、预期过程、预期结果和评分方式的测试用例 |
| Golden Set | 相对稳定、经过校验、用于版本对比和回归的核心用例集 |
| Ground Truth | 人工或可靠系统确认的参考事实、状态或答案 |
| Trace / Trajectory | Agent 执行中的工具调用、参数、结果、状态变化和关键步骤 |
| Outcome | Agent 执行后真实产生的结果或外部状态变化 |
| Scorer | 将执行结果转换为通过/失败、分数或标签的评分器 |
| Rubric | 把主观质量拆成可判断条件的评分标准 |
| Regression | 修改模型、Prompt、工具或代码后重新运行历史用例 |
| Benchmark | 用于横向比较系统能力的标准任务、环境和评测规则 |
| Guardrail | 在输入、执行或输出阶段限制危险和不合规行为的机制 |

## 7. 阅读笔记模板

每份资料只记录能够影响实践的内容：

```markdown
# 资料名称

## 一句话结论

## 解决的问题

## 核心概念

## 评测对象与适用场景

## 数据、指标与评分器

## 可复用方法

## 前提、限制与风险

## 可加入当前评测方案的内容

## 仍需验证的问题
```

不要把原文换一种说法重新抄一遍。笔记必须包含自己的判断、适用条件和一个可执行动作。

## 8. 学习完成标准

满足以下条件，才算完成第一轮学习。每一项都要能结合具体案例口头说明，
不能只背定义：

- [ ] 能在 2 分钟内说明模型评估、Agent 评估、自动化测试和线上监控的区别与联系。
- [ ] 能为一个 Agent 画出执行链路，并从 Outcome、Trace、状态和系统质量四层设计评估。
- [ ] 能建立 Golden Set，选择规则、LLM 或人工评分器，并解释重复运行与统计判断方法。
- [ ] 能设计覆盖正常、边界、依赖失败、状态迁移和对抗输入的分层测试与发布门禁。
- [ ] 能定义线上 SLI/SLO、Trace、告警和回滚流程，并把线上 Bad Case 转成回归用例。
- [ ] 能完成安全威胁建模，并说明最小权限、沙箱、审批、数据保护和审计如何协同。
- [ ] 能拆解单次任务成本及端到端延迟，解释 P50/P95/P99，并提出带质量约束的优化方案。
- [ ] 能比较单 Agent 与多 Agent，说明协作拓扑、通信、共享状态、终止条件和失败归因。
- [ ] 能用“目标—风险—方案—指标—闭环—取舍”在 5 分钟内回答一道系统设计题。
- [ ] 能承受至少三层追问：为什么这样设计、方案何时失效、替代方案如何权衡。

## 10. 学习原则

- 先做小型闭环，再扩充指标和平台。
- 每个模块先简单学习，再复现小 Demo，最后在同一个项目中完整强化。
- Demo 必须保留真实失败和排错证据，不能只演示成功路径。
- 先定义业务中的“成功”，再选择技术指标。
- 先使用确定性规则，再使用模型评分。
- 总分只用于概览，失败样本和根因才用于改进。
- 同一用例必须重复运行，不能用单次成功代表稳定性。
- 公开 Benchmark 用于参考，自己的业务仍需要独立 Golden Set。
- 文档中的阈值、框架和经验不是通用真理，采用前必须用本地数据验证。
