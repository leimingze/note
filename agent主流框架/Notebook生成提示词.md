# 学习 Notebook 生成提示词（通用模板）

> 用途：为任意框架或主题生成「带看懂式」Jupyter Notebook——讲解与代码穿插，先流程图后概念，按执行顺序拆解，核心能力逐个看。代码由 AI 写，读者负责看懂机制。

## 使用方法

1. 复制下方提示词
2. 替换 `{框架名}`、`{目录路径}`、`{日期}`、`{版本}`、`{内核名}`
3. 发送给 AI 后，先对齐结构再生成
4. 生成后要求 AI 实际执行全部无需 API Key 的 cell 验证通过

## 提示词

```text
请为「{框架名}」生成一份带看懂式 Jupyter Notebook，保存到 {目录路径}/demo/{框架名}使用方法.ipynb。
版本基线：{框架名} {版本}（{日期}）。

Notebook 的目标是带读者看懂该框架的核心用法：代码由 AI 写，读者负责看懂机制，
不要设计让读者手写的练习，也不要留空白答题 cell。

必须按以下顺序组织：

1. 标题与说明：写明框架版本、验证日期、学习目标
2. 框架总览流程图：用 mermaid 画一张代表该框架的图，节点用「英文名（中文名）」格式
3. 核心概念表：列出核心概念、作用、在哪个章节可以看到
4. 概念之间的关系：用一条真实可运行场景（如电商订单处理）把全部核心概念串起来，
   配全景 mermaid 图和「概念 ↔ 场景位置」对应表，并给一段可运行的骨架代码
5. 用法拆解：每种用法先给完整代码，再按执行顺序拆解并带入具体输入，逐步追踪状态变化
6. 核心能力逐个看：用可运行的最小例子覆盖该框架的核心特性
   （如循环、并行、持久化、人工介入、流式、多 Agent，按框架实际情况取舍），
   每个能力包含：场景说明、可运行代码、执行顺序拆解
7. 能力总览表：能力 | 场景 | 关键 API
8. 常见问题与下一步

硬性要求：
- 使用中文，专有名词保留英文
- 所有无需 API Key 的 cell 必须真实运行验证通过；需要 Key 的 cell 打上
  requires-api-key 标签并明确标注
- 代码按执行顺序拆解，先运行后拆解
- 流程图提前用 markdown Mermaid 画好放在讲解 cell 里（节点用「英文名（中文名）」），
  不要用代码运行时自动生成（自动生成图布局不可控，且 mermaid 文本无法直接查看）
- 内核固定为 {内核名}，注册命令：
  {目录路径}/.venv/bin/python -m ipykernel install --user --name {内核名}
  --display-name "Python 3 ({框架名})"
- 生成后必须用 nbclient 执行全部无 Key cell 验证，通过后才算完成
```

## 可调整项

- 场景可以换（订单、工单、审批等），但必须真实可运行，且全书用同一条场景贯穿
- 核心能力按框架裁剪：不同框架的核心特性不同，例如 LangGraph 是循环/并行/持久化/人工介入/流式/多 Agent
- 如果框架没有「两种写法」对比，第 5 步按实际情况调整
- 生成脚本建议放 `scripts/`，便于后续修改内容后重新生成
