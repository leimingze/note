# 内容审核流程设计

## 审核范围

系统只审 20 秒以内的短视频。视频的语音转为文本，与抽取的画面一起交给多模态模型（VLM），按附录 C 的类别审核。低俗内容由程序按[审核标签与分级标准](审核标签与分级标准.md)的组合规则分为 L0–L3（第 4 节）。规则表根据审核结果决定放行、限流、人审或拦截。

## 1. 要解决的两个问题

1. **黑灰产持续对抗**：例如在正常视频中插入一闪而过的违规帧来躲过审核。你防住一种，对方马上换下一种。
2. **管控标准经常变**：例如擦边内容，舆情高峰期要严查，风头过去后又放宽。

## 2. 审核流程

### 2.1 主流程：文本、图片、视频分别怎么处理

```text
上传内容
 │
 ├─ 文本 ─→ 归一化：谐音、拆字、变体字、繁简
 │            │
 │            ▼
 │          查违规库：红线词、联系方式、SimHash ──命中──→ 拦截
 │            │ 未命中
 │            ▼
 │          LLM 判定：类别 + 程度 ─→【汇总】
 │
 ├─ 图片 ─→ 并行处理
 │            ├─→ VLM 判定（看画面，也看图中文字的意思）：类别 + 程度 ─→【汇总】
 │            └─→ 检测二维码 ─→【汇总】
 │
 └─ 视频 ─→ 计算原文件 SHA-256，查询当前识别版本的文件审核记录
              ├─ 已有记录 ─→ 复用当前进度或观察结果，按当前规则表处置
              └─ 首次提交 ─→ 创建文件审核任务，进入媒体校验与解码（超过 20 秒或校验失败 → 拒绝）
              │
              ├─ 画面 ─→ 挑帧：每 2 秒一帧 + 画面切换帧 + 短暂插入帧 + 渐变叠加帧 + 局部变化帧，每次请求最多 16 帧
              │            │
              │            ▼
              │          选中的帧保留时间戳，并识别画面文字（OCR）
              │            └─→ 送入下方图文联合审核
              │          全部画面每 0.2 秒检测一次二维码 ─→【汇总】
              │
              ├─ 音轨 ─→ 自动语音识别（ASR）生成带起止时间的转写文本；音频分类标出可疑声音
              ├─ 转写文本 + 画面文字 ─→ 按文本流程归一化，查红线词和联系方式 ─→【汇总】
              ├─ 图文联合审核 ─→ 视频帧、转写文本、画面文字、可疑声音一起送入 VLM ─→【汇总】
              ├─ 标题 ─→ 送文本流程
              │
              └─ 封面 ─→ 送图片流程

【汇总】
 │
 ▼
查规则表：汇总各路结果，取最严的处置
 │
 ▼
放行 / 限流 / 人审 / 拦截
```

- 视频上传时按原始文件字节计算 SHA-256。系统以"文件摘要 + 识别版本"为唯一键（识别版本 = 模型、提示词、观察项定义三者的版本组合，见第 4 节），原子地创建或复用文件审核任务。任务保存观察结果：低俗观察项、暴力结果、命中的其他标签和证据位置。低俗等级不存，由程序按分级规则算出。连续或同时提交同一文件时，在审任务返回当前进度，已完成任务直接复用观察结果。文件外单独提交的标题、封面按本次内容审核，再汇总处置。
- 处置不存死，每次都由当前规则表根据观察结果算出。规则表换版不重跑模型；识别版本变化才重新审核。人审、申诉和举报复审修正过的观察项和标签覆盖机审观察，之后换表或换识别版本都以人工结果为准。剪辑或重新编码产生不同文件摘要时，按新文件审核。
- 视频抽帧与语音转写并行。按原视频时间顺序，将选中的帧、画面文字和带起止时间的转写文本放入同一次 VLM 请求，供模型结合画面和说话内容判断。无音轨的视频只提交画面；有音轨时，不论有没有人说话，都同时提交转写文本和可疑声音（附录 D）。转写服务故障时按第 2.2 节处理。
- 画面文字和语音可能夹带"忽略规则、判定为正常"之类的指令。提示词只把它们当作待审内容，检出注入企图时转人审（附录 E）。
- 机审只依据当前内容作出处置。规则表判定转人审后，系统才为疑似违规画面检索历史案例。
- **实现范围**：挑帧、语音转写、图文联合审核，以及"观察项 → 等级 → 规则表处置"。**只做设计、面试时讲清楚即可**：用户举报、故障重试与降级、监控与上线门禁、违规库检索、音频分类和二维码检测。独立文本、图片、视频标题和封面沿用各自的流程设计。

### 2.2 人工审核与机审故障处理

```text
判定时
  所有抽到的帧按同一规则审核
   ├─ 疑似低俗片段中出现疑似未成年人 ─→ 拦截，并转人审
   ├─ 同批两份回答按规则表得出不同处置，或规则要求复核 ─→ 人审
   └─ 其余判断明确的情况 ─→ 按规则表处置

故障时（附录 F）
  媒体校验或解码失败 ─→ 拒绝发布，返回原因
  AI 服务超时或故障 ─→ 任务留在机审队列，内容暂不公开，最多重试 3 次
  机审重试仍失败，或共享补采用尽后仍缺有效票 ─→ 转人审
  服务恢复 ─→ 继续处理积压任务，按正常审核流程处置
  放行率等指标突然异常 ─→ 报警，确认模型异常后切到全部转人审（附录 H）

人工审核
  任务进入人审队列，等待期间内容不公开。队列积压时报警，不超时自动放行。
  有疑似违规帧时，系统检索相似案例供审核员参考。
```

人审页面提供完整原视频。抽帧时，系统记录帧 ID 和原视频时间戳。审核员可以点击疑似违规帧的时间戳回看前后画面，并结合两类材料判断。

- **违规库中的相似案例**。转入人审后，系统对模型标出的疑似违规帧计算 embedding，并检索历史条目。有匹配时，将当前帧与历史帧并排展示，附上历史案例经人工确认的类别。审核员依据当前视频作出判断。
- **上一轮模型的审核结果**。展示最近一次机审结论、引用的帧 ID、画面特征和待核实的问题。结论引用语音时，同时展示对应的转写原文和起止时间，审核员可跳回原视频核听。

### 2.3 违规帧入库与申诉撤销

```text
审核员查看送审材料并核对原视频
 │
 ▼
审核员确认违规，记录审核结论，并决定是否入库
 ├─ 仅完成审核 → 保存审核记录
 └─ 提交入库 → 审核员选定违规帧或文本片段，系统直接入库并记录违规类别、审核员和规则表版本号
```

- 每个入库帧分配一个唯一条目 ID，并在原审核记录中关联该 ID。违规库保存帧图像、原视频标识、时间戳和向量模型版本，向量索引用同一条目 ID 保存该帧的 embedding。文本条目使用 SimHash。
- **每条记录带规则表版本号和判定依据**：入库时，系统按条目的标签和等级用平时规则表算一遍，记录"平时规则下是否也违规"。只在临时规则下才算违规的条目（如严查期的 L2 擦边），临时规则到期时失效；平时规则下也违规的条目保留。

申诉成功后，复核员在原审核记录中勾选确认误判的帧。系统按所选条目 ID 删除违规库记录，并从向量索引中移除对应的 embedding。申诉记录保留撤销的条目 ID、撤销原因和时间。例如，同一视频有 3 帧入库，复核只推翻第 2 帧，就只删除第 2 帧的条目和向量。

### 2.4 用户举报：放行之后的兜底

```text
用户举报（选择类别，可选填时间点）
 │
 ▼
按视频聚合有效举报
 ├─ 红线类别（涉未成年、色情、违法犯罪、出售违禁品）→ 1 次即限流，优先进复审队列
 ├─ 其他类别 → 有效举报达到 3 次进复审队列，内容保持可见
 └─ 未达到 → 只记录
 │
 ▼
复审：审核员查看原视频、举报类别和时间点、原机审结论
 ├─ 违规 → 下架，修正该文件的观察结果，按 2.3 节入库，加入漏审用例（第 3 节）
 └─ 不违规 → 恢复原处置，记录结果
```

- 同一用户对同一视频只算一次。历史举报多次不成立的用户，举报不计入次数。次数阈值为默认值，按复审成立率调整。
- 确认的漏审要写明原因：挑帧没选中、模型判错，还是规则表放行。三种原因分别对应修改挑帧规则、修改提示词或标签标准、修改规则表。
- 修正后的观察结果按文件摘要保存，同一文件再次上传时直接按修正结果处置。
- 举报在审核服务内聚合。红线类别先调用内容模块的限流接口，再调用内容模块的复审接口（`trigger=report`），由内容模块按复审流程把任务投递回来（2.5 节）。

### 2.5 和内容模块的接口

审核服务独立部署、使用自己的数据库，与 PulseFrame 内容模块只通过接口交互。契约以[内容与发布](../实习项目/PulseFrame/docs/设计/业务模块设计/内容与发布/内容与发布.md)的"审核对接"一节为准。

| 方向 | 接口 | 用途 |
|---|---|---|
| 内容 → 审核 | `POST /internal/review/tasks` | 投递发布审核或复审任务，按 `task_id` 去重 |
| 内容 → 审核 | `GET /internal/review/tasks/{task_id}` | 对账，返回结论或"审核中" |
| 审核 → 内容 | `POST /internal/review/callback` | 回调结论：`pass` / `limit` 通过但限流 / `reject` |
| 审核 → 内容 | `POST /internal/videos/{id}/offline` | 已发布视频改判为下架 |
| 审核 → 内容 | `POST /internal/videos/{id}/limit` | 限流或解除限流，带按视频递增的 `seq`，防止乱序 |
| 审核 → 内容 | `POST /internal/videos/{id}/rereview` | 举报达到阈值时发起复审 |

- 转人审、机审故障重试期间都不回调。视频停在"待审核"，对他人不可见，符合 2.2 节"人审期间不公开"；内容模块每 10 分钟对账一次，拿到"审核中"。
- 审核服务用只读凭证按 `media_key` 读取私有桶里的原文件，自己计算 SHA-256 去重。
- 超过 20 秒的视频在内容模块确认上传时就被拒绝；审核服务仍保留时长校验，作为兜底。
- PulseFrame 的下架状态没有出边，已下架视频不能自动恢复。申诉成功或临时规则到期时，审核服务只解除限流；需要恢复的下架内容列入清单，由运营处理。

## 3. 违规素材识别与漏审验证

- 审核员确认并提交的违规帧，可供后续人审任务按画面相似度检索。
- 漏审主要通过用户举报发现（2.4 节）。每种确认的漏审情况保留一组验收用例，系统更新后用同一组视频复查。
- 识别版本变更前必须通过上线门禁，上线后持续监控放行率等指标（附录 H）。

## 4. 问题二怎么解决：AI 和规则表分开

分三层：模型只记录看到了什么，程序按分级标准算等级，规则表决定处置。

- **模型记录观察项，不直接给等级。** 每个低俗表现记一条，写明类型和时间点。类型取自[审核标签与分级标准](审核标签与分级标准.md)：与场景无关的部位特写、与活动无关的泳装内衣出镜、性暗示动作、带性意味的呻吟或喘息声、性行为或模仿性行为、无正当用途的私密部位展示。另外记录是否属于内衣泳装商品展示、是否出现疑似未成年人。
- **程序按组合规则算 L0–L3。** 例如：特写出现 2 次及以上或累计超过 3 秒，定为 L2；同时出现两种 L2 表现，定为 L3。视频不超过 20 秒，整条视频合在一起定级，每个表现保留时间点供人审回看。
- 暴力检出标记单独进入处置规则表。

分级规则改了（比如 3 秒改成 5 秒），只用已存的观察项重算等级，不用重跑模型。只有观察项本身增加或删除，才算识别版本变化。

例如，对同一条 L2 视频，平时规则可以限流，严查规则可以拦截。两次处置使用同一份画面观察和同一个等级。临时规则设到期时间，到期恢复平时规则。

- 标准变了只换表：不用重新训练 AI，也不用重新标注。
- 换表前先预演：用历史日志按新表重算一遍，看会多拦多少条、人审要多看多少条。
- 换表时连已公开内容一起处理：用已存的观察结果，对最近 30 天公开的内容按新表重算，变严的立即执行下架或限流。临时规则到期后同样按平时规则重算：只因临时规则被限流的内容自动解除限流；已下架的不自动恢复（PulseFrame 的下架状态不能恢复，见 2.5 节），列入清单由运营处理。

## 5. 局限（面试时主动讲）

- 验收用例覆盖预先选定的画面变化，检出率只描述这些样本上的表现。
- 渐变叠加和局部变化检测都依赖阈值，透明度极低或面积极小的插入仍可能漏掉，主要靠用户举报兜底。
- 用户举报依赖曝光，播放量很少的漏审内容很难被举报发现。
- 数据里违规内容的比例远高于真实平台，只能看相对变化。
- 换表预演会低估影响：被前面环节（如文本红线词）拦下的内容没有完整的观察记录。
- 模型只看到抽出的帧，"累计超过 3 秒"只能按相邻帧的时间戳估算，定时帧间隔 2 秒，时长判断比较粗。
- 音频分类会把运动喘息、疼痛呻吟误判成可疑声音，需要靠画面区分；只有声音没有画面线索时，只能转人审。
- 语音识别错误会影响模型对语境的判断，可回听模型引用的时间段核对转写内容。

## 附录：细节

### A. 挑帧规则

- 只审 20 秒以内的视频，每 2 秒一帧的定时帧最多 10 帧。以下检测都在全部解码帧上进行，选中的帧与转写文本一起交给 VLM 审核。
- **短暂插入**：相邻帧差超过阈值，且 0.5 秒内变回原画面，取插入段里与插入前画面差异最大的一帧（插入段紧挨转场闪白时，中间一帧可能正好是转场帧）。按时长判断，插入 1 帧和插入 10 帧都能覆盖。镜头移动时"变回原画面"按缩略图的相对差判断。
- **画面切换**：相邻帧差超过阈值且不再变回，取切换后的第一帧。
- **渐变叠加**：每帧减去前后各 1 秒画面的中位数背景，得到残差。残差超过阈值的时段，取残差最大的一帧。背景窗口明显长于渐入渐出时长，所以慢慢淡入的半透明画面也会留下残差。残差用 16×9 彩色缩略图计算，再减去残差自身的滑动中位数基线，镜头匀速移动时不误报；画面切换前后 1 秒内不判。
- **局部变化**：把画面切成 3×3 九宫格分块计算帧差。只有个别块突变时，取该帧，并把变化区域裁剪放大，与整帧一起送审，用来应对角落画中画。
- 按原视频帧号去重，再按时间升序每 16 帧分一批，末批可以少于 16 帧。相同帧号只保留一个类型标记。各批随附标题、全片 ASR 转写和 OCR 文字。
- 短暂插入、局部变化、渐变叠加三类帧合计超过 5 个时，视为刻意规避，同时转人审。
- 阈值已用 86 个正常视频合成的插帧视频标定（约束：正常视频平均不超过 16 帧、疑似规避比例不超过 5%）：画面切换帧差 0.15，变回判定帧差 0.04（相对差 0.6），短暂插入窗口 0.5 秒，渐变残差 0.02，分块帧差 0.15、其余块静止上限 0.06、最多 1 块突变，疑似规避门槛 5 个。在另外 214 个视频上，硬插 1/3/10 帧的选中率为 99.5%/98.6%/97.2%，30%/50% 渐变叠加为 65.4%/75.7%，角落画中画为 91.1%；均匀抽帧分别为 2.3%/8.9%/20.1%、11.7%/11.7%、50.9%。
- **可疑帧单独复核**：从短暂插入、局部变化、渐变叠加三类中按时间取前 16 帧，仅带画面，独立采样两次。普通镜头切换帧和定时帧只参加主审。复核只判断视觉低俗和暴力线索。
- **插帧规则**：主审观察项对应可疑时刻，或复核检出视觉低俗、暴力时，交规则表综合处置。复核结果有分歧且影响处置时提交人工。
- 待定：人审规则需要写明"确认是刻意插入的违规画面时如何处置"。目前人审标准里单处轻微擦边放行，插帧视频转到人审后仍可能被放行。

### B. 违规库

验收素材与违规库分别保存。违规库从空库开始，按第 2.3 节的确认流程写入条目，再用已转人审的疑似违规帧检查案例检索结果。

图像检索使用同一模型版本生成查询向量和库内向量，按余弦相似度从高到低返回达到阈值的历史案例。用同一素材经过压缩、缩放或裁剪后的画面，以及外观相近的正常画面校准阈值。相似度用于筛选候选案例。

写入和删除流程见 2.3 节。

### C. 审核类别

KuaiMod 官方评测脚本列出 16 类，CH-SV 有 6 类。项目合并三组对应标签：正向／正常、色情低俗／Vulgarity、不实信息／Fakeness，共 19 类。CH-SV 的冒犯（Offense）范围较广，与 KuaiMod 的“辱骂、引战、宣扬仇恨”分别保留。L0–L3 是项目内的低俗分级，按表中的组合规则定级，不计分。转人审是判定结果，不算类别。[审核标签与分级标准](审核标签与分级标准.md) · [KuaiMod 评测脚本](https://raw.githubusercontent.com/KuaiMod/KuaiMod.github.io/main/evaluation/multi_cls_eval.py) · [CH-SV 类别说明](https://raw.githubusercontent.com/DLUTSSL/CH-SV/main/README.md)

### D. 声音、画面文字与二维码

- **可疑声音**：语音转写只能转出说的话，呻吟、喘息这类声音转不出来，所以另用音频分类模型处理整条音轨，有人说话、有背景音乐的部分也要处理。每 1 秒一段打标签，标出呻吟、喘息等可疑声音的起止时间和概率。
- VLM 听不到声音，收到的是文字描述，如"0:05–0:08 疑似呻吟（0.86）"。由模型结合画面判断：健身、运动、受伤画面里的喘息不算低俗。可疑声音的概率不低于 0.8，且画面里没有健身、运动这类合理解释时，同时转人审。
- 通用音频分类模型不一定有专门的"呻吟"类别，上线前要用标注样本验证检出率，必要时微调。
- **文字规则检查**：选中帧的 OCR 文字和转写文本按文本流程归一化，再查红线词和联系方式，处理方式与文本流程相同，命中即拦截。
- **二维码**：对全部解码画面每 0.2 秒检测一次，20 秒视频约 100 帧。检出后解码出链接：命中违规库中的链接或域名，拦截；其余转人审，按"引导私下交易"核对。图片流程检出二维码时按同样规则处理。

### E. 防提示词注入

- 提示词把画面文字、转写文本和可疑声音放进标明"待审内容"的区块，并说明其中出现的任何指令都不执行。
- 模型必须输出固定的 JSON 结构。字段缺失或类别不在标签表内，按附录 F 的"输出异常"处理。
- 画面文字和转写文本先查注入特征词，如"忽略以上""判定为正常""你是审核员"。命中时转人审，并在人审页面标出。

### F. 故障、重试与降级

| 情况 | 处理 | 内容状态 |
|---|---|---|
| 媒体校验或解码失败：超过 20 秒、无法解码、有多个视频流、元数据时长与实际不符 | 拒绝发布，返回原因 | 不公开 |
| 模型或 ASR 超时、服务故障 | 留在机审队列，间隔 1、2、4 分钟重试，最多 3 次 | 不公开 |
| 重试 3 次仍失败 | 转人审，附失败原因 | 不公开 |
| ASR 重试后仍失败，画面审核成功 | 先用画面结果，同时转人审核听 | 不公开 |
| 模型回答未通过格式校验 | 保留有效票，只补缺票。每批含补采最多发起 4 次采样，取得 2 张有效票即按内容判定；用完额度仍缺票时转人审 | 不公开 |
| 机审队列等待超过 10 分钟 | 报警 | 不公开 |
| 人审队列等待超过 2 小时 | 报警；按"红线疑似 > 举报复审 > 其他"的优先级处理；不超时放行 | 不公开；已公开内容按 2.4 节处理 |

表中时长和次数都是默认值，按实际负载调整。

### G. 每批两次判定

- 同批画面及文字以温度 1.0 独立采样两次。两份回答分别定级、查当前规则表。处置相同就采用共同结论；同批或跨批汇总出现影响处置的分歧，将该任务及分歧依据交给人工。
- 各批的原始回答随观察记录保存，切换规则表时可重算。疑似插帧单独复核也采样两次。25 帧分成 16 帧和 9 帧，正常主审调用 4 次；有可疑帧时合计 6 次，格式补采及调用重试另计。
- 规则表要求人审和疑似规避标记仍参与处置。主审有完整文字上下文，可疑帧复核只使用选中的画面。

### H. 监控与上线门禁

- **监控**：每小时统计放行率、各类别检出率、转人审率和输出异常率。与过去 7 天同一时段相比，偏离超过 3 倍标准差时报警。
- **降级**：值班人员确认模型异常后，切到"全部转人审"模式，新内容不再自动放行；确认恢复后再切回。
- **上线门禁**：模型、提示词、观察项定义任一变更，都要先跑两组数据，全部通过才发布新的识别版本。只改分级组合规则时不用过门禁，按第 4 节用历史观察项预演即可：
  - KuaiMod test 集（1000 条截图）：准确率比当前版本下降不超过 2 个百分点。
  - 漏审用例集（第 3 节）：不允许新增漏检。
  - 低俗观察项标注集（待建，KuaiMod 只有类别标签，覆盖不到观察项）：各观察项检出率不低于当前版本。
