# AI 内容审核闭环设计（STAR）

用 VLM + 判例库做短视频审核，策略按版本发布，并用 KuaiMod 测试集分周期回放模拟反馈，跑通"判定 → 处置 → 反馈回收 → 策略变更 → 离线验证 → 发布/回滚"的闭环。策略变更有四条通道：提示词、阈值、判例库、模型微调（LoRA SFT + DPO）。微调在租用的云 GPU 上进行。

本项目是练手项目，目标是证明理解 AI 审核的完整流程和其中的工程取舍，不证明在真实业务流量上可靠。

---

## S：背景

### 业务背景

PulseFrame 的内容与发布模块已经定义了审核服务契约（见 `实习项目/PulseFrame/docs/设计/业务模块设计/内容与发布/内容与发布.md` 的"审核对接"一节）：

- 投递：`POST /internal/review/tasks`，以 `task_id` 去重，`kind` 为 `publish`（发布审核）或 `rereview`（复审）。
- 回调：`POST /internal/review/callback`，`result` 只有 `pass | reject`，附 `reason`。
- 查询：`GET /internal/review/tasks/{task_id}`，供对账。
- 发布审核是先审后发，结论时效目标 P95 ≤ 5 分钟。已发布视频的复审由曝光量、举报或人工触发。

内容与发布模块目前用一个模拟审核服务占位，真正的审核服务还没有实现。

### 参考方法

论文 *VLM as Policy: Common-Law Content Moderation Framework for Short Video Platform*（arXiv 2504.14904，KDD 2025）提出"判例法式"审核：VLM 结合结构化 CoT 做判定，离线 SFT + DPO，线上靠用户反馈天级更新。

开源部分只有 HuggingFace `KuaiMod/KuaiMod` 的 test split（约 1000 条，字段为 tag / title / OCR / ASR / images（封面 + 最多 8 帧）/ pid，许可 CC-BY-NC-4.0）和评测脚本。训练数据、prompt、训练代码、模型权重和在线闭环都未开源。

本项目借用的是它的思路，不复现它的指标：

- 判例是策略的一部分。
- 策略要随反馈迭代。
- 判定要输出可审计的理由。
- 用户反馈可以转成偏好数据去更新模型。论文按天更新，本项目改为按周期批处理。

### 约束

| 约束 | 影响 |
|---|---|
| 单人开发，无标注团队 | 真值只能来自已有人工标签，即 KuaiMod 的 tag |
| 按需租用云 GPU，默认 24GB 显存，必要时升到 48/64GB | 默认对 Qwen2.5-VL-3B-Instruct 做 LoRA 微调；GPU 只在训练和批量评估时租用，按小时计费 |
| KuaiMod 只有约 1000 条 | 训练数据和评测数据互相挤占；留出集绝对不参与训练。训练数据可用清洗后的外部公开数据扩充（见 A8 外部数据），但门禁只用 KuaiMod 留出集 |
| 没有真实流量 | 反馈靠回放测试集模拟，灰度没有意义 |
| 数据许可为非商用 | 项目仅限学习用途；数据集和由它训练出的权重都不对外发布 |
| 已有 Go 后端（MySQL + Redis） | 审核服务用 Go 实现，复用现有基础设施；训练脚本用 Python |

## T：任务

### 目标

1. 实现一个满足上述契约的审核服务，PulseFrame 上传的视频能真实走完审核流程。
2. 建立策略版本化机制：提示词、阈值、判例集、模型合成一个版本，整版发布、整版回滚。
3. 用 KuaiMod 测试集搭建离线回放实验，模拟多个周期的反馈和策略迭代。
4. 实现批处理版的反馈学习：先用一次性标注的数据（KuaiMod 冷启动集加清洗后的外部公开数据）做 SFT 和离线 DPO，再把各周期暴露并确认的错例转成 DPO 偏好对，周期性更新 LoRA 权重。
5. 能回答"哪一次策略改动，让误杀率和召回各变了多少，置信区间多大"，包括模型权重的改动。

### 非目标

| 不做 | 原因 |
|---|---|
| 全参数训练 | 数据只有几百条，全参训练只会过拟合；瓶颈是数据，不是显存 |
| 天级重训、在线学习、自动发布模型 | 数据量撑不起高频训练；每次权重更新都要过发布门禁 |
| 对齐论文指标（92.4% 等） | 数据、模型、政策都不同，指标不可比 |
| 线上动态修改策略 | 会破坏归因；所有改动走版本发布 |
| 在线灰度 | 没有流量，统计上测不出差异；用离线回放代替 |
| 扩充分类体系 | 沿用 KuaiMod 的 tag，政策口径以快手标签为准 |
| 全自动处置 | 中间置信段必须转人审 |

### 验收标准

以下四个场景能在回放实验中复现，并由周期报告自动给出结论：

1. **新类型冒头**：从第 2 周期起放入冷启动集和第 1 周期都没有出现过的类别，系统漏判；新增判例并发版后，延后类别的召回回升，且超出置信区间。召回按全部延后类别合并统计，样本来自留出集，加上发版后才到达、从未用于修改策略的周期数据。
2. **失败改动被拦截或回滚**：一个过激阈值的版本让误杀率显著上升，被发布门禁拦下；或者强制上线后，通过一次回滚恢复。
3. **过拟合被识破**：候选版本在已用周期数据上提升，留出集上不提升，发布门禁拒绝。
4. **微调效果可归因**：换基座模型、SFT、加入外部数据、离线 DPO、反馈 DPO 各自是一个版本，各自过门禁，报告给出每一步的独立贡献。"没有显著提升"也是有效结论，如实记录。

## A：行动

### A1 总体架构

```text
PulseFrame 内容与发布
   │  POST /internal/review/tasks
   ▼
审核服务（Go）
   ├─ 任务接收（task_id 去重，落库）
   ├─ 预处理 worker：抽关键帧 / OCR / ASR → 结构化输入
   ├─ 判定 worker：加载当前策略版本 → 检索判例 → 调 VLM → 解析结构化输出
   ├─ 分级处置：reject / 转人审 / pass
   ├─ 回调 PulseFrame（退避重试）
   └─ 决策日志（每条判定绑定策略版本号）

VLM 推理端（OpenAI 兼容接口）
   ├─ 云 GPU 上的 vLLM：基座模型 + 多个 LoRA adapter，按名称选择（线上主线）
   └─ 商用 API：只用于 v0 参考基线和教师模型，不进入线上主线

离线部分
   ├─ 数据加载：KuaiMod → 统一的结构化输入（Go）
   ├─ 回放实验：按周期运行、生成模拟反馈、产出周期报告（Go）
   ├─ 训练数据构造：CoT 生成、偏好对构造（Python）
   ├─ 训练：LoRA SFT / DPO（Python，ms-swift，云 GPU）
   └─ 发布门禁：候选版本 vs 当前版本，在留出集上对比（Go）
```

在线判定和离线回放用同一套"结构化输入 → 判定 → 结构化输出"代码。回放验证过的东西，就是线上会跑的东西。

商用 API 和 vLLM 都走 OpenAI 兼容接口，判定代码不区分两者。换模型只改策略版本中的模型字段。

线上主线从一开始就用开源模型，而不是商用 API。原因是 DPO 的负例必须来自被训练的那个模型自己的错误；如果线上跑的是 API，暴露出来的错例就是 API 的错，拿来训练开源模型属于用别人的错误分布训练，偏好对就失去了意义。商用 API 版本 v0 只作为参考基线，报告中给出主线和它的差距。

### A2 输入预处理

| 来源 | 处理 |
|---|---|
| KuaiMod 回放 | 数据集已有 title / OCR / ASR / 封面与帧，直接转成结构化输入，不经过预处理管线 |
| PulseFrame 真实上传 | ffmpeg 场景切换检测加均匀补帧，取封面 + 最多 8 帧；OCR 和 ASR 由 Python sidecar 完成（PaddleOCR、faster-whisper） |

只送最多 8 帧给 VLM，和 KuaiMod 的输入形态一致，回放和线上的判定条件也一致。更密的抽帧只在 OCR 和画面哈希中使用。

图片分辨率是训练和推理共用的参数。训练时用什么分辨率，推理时也必须用同一个，所以它记入策略版本。

预处理有版本号（抽帧参数、OCR/ASR 模型版本、图片分辨率），记入决策日志。

### A3 判定

**输入**：结构化输入 + 当前版本的政策说明 + 检索出的 k 条判例（k ≤ 5）。

**输出**（JSON，严格校验，校验失败重试一次，仍失败转人审）：

```json
{
  "label": "违规类别 tag 或 normal",
  "violation": true,
  "rationale": "一段话说明依据",
  "cited_cases": ["case_012", "case_031"],
  "evidence": ["frame_3: ...", "ocr: ..."]
}
```

参考论文作者的经验，推理和结论在一次调用中整体输出，不拆成多步调用。拆开会导致错误累积，成本也更高。微调时的训练目标也是这一整段 JSON。

**置信度**：不采用模型自己报的置信度，因为这类数值没有经过校准。同一输入以 temperature > 0 采样 5 次，`violation=true` 的比例作为违规分数，取值为 0、0.2、0.4、0.6、0.8、1。

采样 5 次而不是 3 次：3 次只有 4 档分数，阈值几乎没有可调空间；主线是自建推理，多采样只增加 GPU 时间。v0 参考基线同样采样 5 次，保证口径一致。

微调后模型容易变得过度自信：5 次采样总是一致，中间置信段消失，人审分流随之失效。因此每个版本都要统计中间段占比，门禁中有对应规则（见 A9）。

**一致性校验**：如果 `rationale` 和 `label` 自相矛盾（例如理由写"未见违规"，标签却是违规），这条判定转人审，并计入"不一致率"指标。

**成本控制**：判定结果按 `(sample_id, policy_version 的判定相关哈希)` 缓存。同一版本重复回放不重复调用。每次调用的输入/输出 token 数记入日志；自建推理另外记录 GPU 时长。成本按实测汇总，不做事前假设。

### A4 分级处置

| 违规分数 | 处置 | 回调 |
|---|---|---|
| ≥ 高阈值 | 自动驳回 | `reject`，reason 取 rationale 摘要 |
| 介于两个阈值之间 | 进入人审队列 | 人审结论出来后再回调 |
| ≤ 低阈值 | 自动通过 | `pass` |

阈值属于策略版本的一部分，只能在冷启动集和已用周期数据上调整，不能用留出集调。

换模型后分数分布会变，旧阈值不再适用。因此模型变更时，阈值按固定程序在冷启动集上重新标定：取使误杀率不超过目标值的最低高阈值，再取使漏判率不超过目标值的最高低阈值，目标值写在版本中。程序本身是固定的、不可人为干预，所以它算作模型变更的一部分，不违反"一个版本只改一类东西"。门禁报告同时给出旧阈值和新阈值下的指标，便于区分模型本身的变化和阈值的变化。

**人审队列和 5 分钟时效有冲突**：进入人审的任务会超出时效，由 PulseFrame 的对账逻辑看到"审核中"。本项目中人审由开发者本人在简易后台完成。时效指标只统计自动处置的任务，人审占比作为单独指标展示。

**复审**：`kind=rereview` 走同一流程。`trigger=report` 的复审本身就是一条反馈信号，见 A7。

### A5 判例库

判例是策略的外部资产，不压进模型权重。新违规类型出现时，加一条判例并发布新版本即可生效，不需要训练。

```text
case
  case_id       判例编号
  tag           所属类别
  verdict       违规 / 不违规（边界反例同样重要）
  summary       内容摘要（文字描述；附 1 张关键帧引用，只供人查看，不注入 prompt）
  reasoning     为什么这样判
  source        来源：哪个周期的哪条反馈
```

- **注入方式**：判例只以文字形式注入 prompt。如果每条判例都带图，5 条判例加上样本自身的 9 张图，图片 token 和显存都会翻倍。
- **检索**：按类别 + 文本相似度（title / OCR / ASR 拼接后做向量检索）取前 k 条。规模在几十条以内时，用全量向量的暴力检索即可，不引入向量数据库。
- **规模上限**：30 条。超过时先合并同类判例，再考虑扩容。
- **冲突检测**：每次发版前，在留出集上对比"判定翻转、且翻转是因为召回的判例集合变了"的样本，比例超过 5% 即视为判例互相矛盾，不允许发布。

**判例和微调的分工**：

| 问题 | 走哪条通道 | 原因 |
|---|---|---|
| 新违规类型（训练数据里没有） | 判例 | 模型学不会没见过的类别；判例小时级就能生效 |
| 已知类别的边界反复判错 | 微调 | 同类错误积累到一定数量后，写进权重比堆判例更稳 |
| 输出格式不稳 | 微调（SFT） | 提示词约束无效时，SFT 修格式最直接 |
| 一次性的特殊情况 | 都不走 | 记录即可，避免为个例改策略 |

微调的训练样本里包含注入判例后的完整 prompt。这样模型学到的是"参考判例做判断"，而不是把判例背进权重。

### A6 策略版本与留痕

一个策略版本是一份不可变的清单：

```text
policy_version
  version            v0, v1, ...
  parent_version     基于哪个版本修改
  change_type        prompt / threshold / cases / model（一个版本只能是其中一种）
  prompt_hash        政策说明 + 输出格式 prompt
  thresholds         高/低阈值
  case_set_hash      判例集快照
  model_ref          见下
  preprocess_ver     预处理版本（含图片分辨率）
  change_note        这次改了什么、为什么
  status             candidate / active / retired / rejected

model_ref
  商用 API：         供应商 + 带日期的模型快照名，不使用浮动别名
  自建模型：         基座模型名与版本 + adapter 文件哈希
                     + 训练数据清单哈希 + 训练配置哈希
```

自建模型的 `model_ref` 写到训练数据清单哈希这一级，所以"这个模型是用哪些样本训出来的"可以一路追到 `decision` 和 `feedback` 表。

决策日志的每一行都指向一个版本：

```text
decision
  task_id / sample_id
  version
  label, violation_score, rationale, cited_cases
  action             reject / human / pass
  final_label        人审或真值（回放中取 KuaiMod tag）
  tokens_in / tokens_out / latency_ms
```

有了这两张表，"版本 v3 相对 v2 让误杀率变了多少"就是一条按版本分组的查询。

**一个版本只改一类东西**。否则提升无法归因到具体改动。换基座模型和训练 adapter 是两次独立变更。唯一的例外是模型变更附带的阈值重新标定（见 A4），它由固定程序完成。

### A7 回放实验

**数据切分**（数据集不入库，放在 `.gitignore` 的数据目录里）：

| 部分 | 规模 | 用途 |
|---|---|---|
| 留出集 | 300 条，分层抽样 | 只用于发布门禁，只看总体指标，不看具体错例，**永不参与训练** |
| 冷启动集 | 300 条 | 模拟上线前一次性标注的数据：用于 SFT、阈值标定和第一批判例，使用全部真值 |
| 周期数据 | 400 条，分 4 个周期，每周期 100 条 | 模拟上线后每个周期新到的流量和反馈 |
| 延后类别 | 选 2–3 个 tag，不进入冷启动集和第 1 周期，从第 2 周期起放入 | 模拟新违规类型出现 |

动手前先统计各 tag 条数。留出集中正例少于 30 条的类别，不出单类结论，只计入总体指标。

延后类别要满足一个硬性条件：合并后在留出集中至少有 30 条正例，并且在第 3–4 周期中至少还有 30 条。达不到这个数量，场景 1 就只能定性展示，测不出显著性。M0 统计后如果没有满足条件的类别组合，就把场景 1 降级为定性展示，并在报告中写明原因。

**每个周期的流程**：

```text
1. 当前 active 版本跑本周期 100 条（主线为开源模型，见 A1）
2. 生成模拟反馈：
     误杀（判违规、真值正常）→ 以 80% 概率产生申诉
     漏判（判正常、真值违规）→ 以 30% 概率产生举报
     正确通过的内容           → 以 2% 概率产生恶意举报
3. 反馈不是标签：申诉和举报只决定"哪些样本送人审"，
   人审结论取 KuaiMod 真值，模拟人工复核
4. 开发者阅读确认后的错例，产出一个候选版本（只改一类东西）
5. 发布门禁（见 A9）
6. 生成周期报告
```

漏判只有被举报才能发现，这就是真实系统里"漏判被系统性低估"的来源。周期报告同时给出"系统看到的错误数"和"真实错误数"，展示两者的差距。

**指标**：

- 二分类：以 `violation` 判断，计算违规召回、误杀率（正常内容被判违规的比例），附 Wilson 95% 置信区间。判成违规但类别判错，在二分类中算对，在多分类中算错。
- 多分类：样本量 ≥ 30 的类别出单类 F1，其余只计入 macro 汇总。
- 运行指标：人审占比、中间置信段占比、输出格式失败率、理由与标签不一致率、单条平均 token。

每个周期 100 条时，单个比率的标准误约 3pp。所以周期数据只用来找错例，不用来判断版本好坏。

### A8 微调通道

**训练数据来自哪里**：

| 阶段 | 数据 | 对应的真实场景 |
|---|---|---|
| SFT | 冷启动集 300 条，使用全部真值；之后加入外部 SFT 池（见下文"外部数据"） | 系统上线前一次性标注的冷启动数据，加上采购或公开的标注数据 |
| 离线 DPO | 外部 DPO 池：当时 active 模型在这批有标签的数据上犯的错 | 上线前用已标注数据做偏好优化 |
| 反馈 DPO | 第 1–3 周期中被反馈暴露、并经人审确认的错例 | 线上反馈回流。只用被暴露的错例，没暴露的错误模型同样看不到 |

DPO 只使用暴露出来的错例，保持模拟诚实：真实系统拿不到没被举报的漏判，训练时也不该用。代价是偏好对很少。粗估：3 个周期共 300 条，错误率 10–20% 时有 30–60 条错例，其中误杀大部分会被申诉、漏判约三成会被举报，最终偏好对大约 20–40 对。每条错例的 5 次采样中，每个错误输出都可以单独作为负例，所以偏好对数可以比错例数多，但它们来自同一批样本，不算独立数据。具体数量**需要实测**。

偏好对这么少，反馈 DPO 大概率测不出显著提升。在本项目中，反馈 DPO 主要用于展示"反馈 → 偏好数据 → 权重更新 → 门禁"这条链路，效果如实报告。偏好数据的数量主要由离线 DPO 提供。

第 4 周期在 DPO 版本发布之后运行，是 DPO 唯一一份从未接触过的新数据，用来做发布后的前瞻检查。

延后类别不在冷启动集中，SFT 学不到这些类别。它们只能靠判例，这也是 A5 中分工的依据。

**外部数据**

KuaiMod 只有 1000 条，扣掉留出集后，训练可用的只有冷启动集 300 条。外部公开数据只用来扩充训练数据，不进入留出集，也不进入反馈周期：

| 用途 | 是否使用外部数据 | 原因 |
|---|---|---|
| SFT、离线 DPO | 使用 | 训练数据是主要瓶颈 |
| 发布门禁（留出集） | 不使用 | 门禁衡量的是快手政策口径；混入外部数据，指标含义就变了 |
| 反馈周期 | 不使用 | 周期模拟的是同一个平台的流量；混入其他平台的内容和标注口径，反馈就不再代表同一套政策 |
| 诊断 | 使用，作为外部验证集 | 按来源分别统计，用于发现捷径学习，不参与门禁 |

**清洗流程**（每一步都记录每个来源处理前后的条数）：

1. **准入**：许可允许研究使用；数据收集方式有文档说明；只从官方渠道获取。**爬取来源的色情类数据集一律不用**：这类数据集存在混入违法内容（包括涉及未成年人的内容）的风险，下载本身就不可接受。色情类别只依靠 KuaiMod 自身的数据。
2. **统一形态**：视频走 A2 的预处理管线（封面 + 最多 8 帧、OCR、ASR），转成和 KuaiMod 相同的结构化输入；单图数据只有封面，没有帧；纯文本数据默认不使用，因为推理时每条样本都有图，用无图样本训练会让模型学到只看文字判断。
3. **标签映射**：建立映射表，把来源标签映射为 KuaiMod tag、normal 或丢弃。只有语义明显属于某个 KuaiMod tag 时才映射，拿不准的一律丢弃。来源数据里的"正常"**不直接映射为 normal**：在别的平台不违规，不等于不违反快手的其他类别。这些样本先由教师模型检查是否命中其他 KuaiMod 类别，没命中的才作为 normal。这一步用的是模型判断（银标），只用于训练数据，不用于评测。
4. **排除延后类别**：映射到延后类别的外部样本全部丢弃。否则模型在 SFT 时就见过这些类别，场景 1 的"新类型冒头"就不成立了。
5. **去重**：外部数据内部去重；再和 KuaiMod 全部 1000 条去重，方法是帧的感知哈希加上标题/OCR 的文本相似度，**和留出集近似重复的样本全部丢弃**。FakeSV 含有快手视频，和 KuaiMod 重叠的可能性尤其要检查。
6. **质量过滤**：文件损坏、时长过短、抽不出有效帧的样本丢弃。
7. **映射一致性检验**：按 A8 的方法生成 CoT 时，如果某个来源（或某个映射标签）的 CoT 过滤丢弃率超过 30%，说明教师模型经常不同意映射后的标签，即映射不可靠，整个来源或这个标签全部丢弃。
8. **配比**：外部数据总量不超过 KuaiMod 冷启动集的 3 倍，单一来源不超过外部数据总量的 50%，避免外部口径盖过快手口径。比例是初始值，按 v_b2 的门禁结果调整，每次调整都是一个新版本。
9. **切分**：清洗后的外部数据按来源分层切成三份：外部 SFT 池、外部 DPO 池、外部验证集（每个来源 50–100 条），三者互不重叠。

每个来源的名称、版本、许可、获取日期，以及每一步处理前后的条数，写入数据清单。清单的哈希进入 `model_ref`。外部数据和 KuaiMod 一样不入库、不再分发。

**捷径学习检查**：外部数据来自不同平台，画面风格、分辨率、水印都不同，模型可能学会"监控画面就是暴力"这类来源特征，而不是内容本身。检查方法有两个：
- 外部验证集上的准确率比 KuaiMod 留出集同类别高出 15pp 以上，说明模型很可能在认来源。
- KuaiMod 留出集上正常内容的误杀率显著上升，说明外部口径污染了快手口径。

出现任一情况，先下调相应来源的配比，再重训。

**CoT 训练目标的构造**（参考论文 Tag2CoT 的思路，具体 prompt 自行设计）：

1. 把真实标签和样本一起交给一个更强的模型（教师模型），让它写出符合 A3 输出格式的理由。
2. 过滤：教师输出的 `label` 必须和真实标签一致；`cited_cases` 必须是实际注入过的判例。不满足的直接丢弃，不修补。
3. 教师模型和被训练的基座模型不能是同一个模型。
4. 只对训练集做这一步，不对留出集做。
5. 使用前确认教师模型 API 的服务条款允许用其输出训练模型。
6. 人工抽查 30 条通过过滤的 CoT，检查理由是否真的基于样本内容，而不是只复述标签。合格率低于 80% 时修改教师 prompt 后重新生成。标签一致只能说明结论对，不能说明理由对。

**DPO 偏好对**（离线 DPO 和反馈 DPO 格式相同，只是来源不同）：

```text
prompt   = 当时线上版本的完整输入（含注入的判例）
chosen   = 按上面方法、以真实标签生成并通过过滤的输出
rejected = 当时模型自己的错误输出（取自 decision 表，原样使用）
```

负例使用模型自己真实犯过的错，不另外编造，这样偏好对针对的是模型实际的错误分布。离线 DPO 的做法是：当前 active 模型对外部 DPO 池推理一遍，判错的样本组成偏好对。这些样本有标签，所以不需要等反馈暴露。外部 DPO 池和 SFT 池不重叠，以免模型在训练过的样本上几乎不犯错，导致没有负例。

**训练配置**：

- 框架：ms-swift（论文作者内部实验同样使用 Swift，并支持多模态 SFT 和 DPO）。
- 基座：默认 Qwen2.5-VL-3B-Instruct（3B 多模态 VLM，可看视频帧），并沿用 KuaiMod 输入形态接入。更大的基座（8B 及 30B 级）不作为默认，原因是瓶颈在数据而不在模型容量；只有当当前基座的 DPO 版本出现显著提升、而且零样本对比显示更大基座明显更强时，才作为一次独立的 `change_type=model` 变更尝试，同样要过门禁。
- 方式：LoRA，bf16，开启 gradient checkpointing。DPO 的参考模型就是关掉 adapter 的基座模型，不需要额外加载一份。
- 显存：Qwen2.5-VL-3B 模型的 LoRA 加上最多 9 张图，在 24GB 显存内应当可行。**需要实测**：先用 batch size 1 跑通一步，记录峰值显存。超出 24GB 时升到 48/64GB 实例，不降低图片分辨率和帧数，保持输入和 KuaiMod 一致。只有改用更大基座（8B/30B 级）时才相应上调显存档位。
- 训练结束后保存 adapter、训练日志、数据清单和配置，四者的哈希写入 `model_ref`。

**版本链**：

```text
v0    商用 API 零样本                          参考基线，不上线
v_a   开源基座，零样本                          主线初始版本
v_b1  SFT（只用冷启动集）                       change_type=model
v_b2  SFT（冷启动集 + 外部 SFT 池）              change_type=model，和 v_b1 比较
v_c1  当前 active 模型 + 离线 DPO（外部 DPO 池）  change_type=model，第 1 周期前发布
...   第 1–3 周期中的提示词/阈值/判例版本
v_c2  当前 active 模型 + 反馈 DPO               change_type=model，第 3 周期后发布
...   第 4 周期：前瞻检查
```

v_b1 和 v_b2 的训练配置相同（同样的超参数和 epoch 数），只有训练数据清单不同。两者都从基座开始训练，门禁中 v_b2 和 v_b1 比较，所以外部数据的贡献可以单独读出。v_b2 没有通过门禁时，主线沿用 v_b1，外部数据只保留离线 DPO 一种用途，也要单独评估。

v_a 是微调的对照组。不拿 SFT 版本直接和 v0 比，否则说不清提升来自换模型还是来自微调。

DPO 在当时的 active 模型上继续训练：如果 SFT 版本都没通过门禁，active 仍是 v_a，DPO 就从基座开始训练，负例也来自 v_a。始终保证负例出自被训练的那个模型。

v_c2 和它的父版本之间夹着若干个提示词/判例版本，门禁比较的是 v_c2 和它的直接父版本，所以反馈 DPO 的贡献仍然可以单独归因。

**GPU 使用方式**：

- 训练和批量评估集中安排，跑完就释放实例，不常驻。
- 推理用 vLLM 同时加载基座和多个 LoRA adapter，按名称选择。切换或回滚模型版本不需要重新部署。
- 每次租用的时长和费用记入报告。

### A9 发布门禁与回滚

候选版本和当前 active 版本都在留出集上运行，按样本配对比较：

| 条件 | 判定 |
|---|---|
| 误杀率或召回显著变差（McNemar 检验 p < 0.05） | 拒绝 |
| 提示词、阈值、判例变更：已用数据上的提升超过留出集提升的 2 倍，或两者相差超过 5pp | 拒绝，判为过拟合 |
| 判例冲突翻转率超过 5% | 拒绝 |
| 中间置信段占比低于 2%，而留出集上的错误率没有显著下降 | 拒绝，判为置信度失效 |
| 都未触发，且至少一项指标显著变好 | 发布 |
| 都未触发，但没有显著变化 | 不发布，记录"无效改动" |

过拟合规则不用于模型变更。模型在训练数据上的指标必然大幅高于留出集，套用这条规则，每次微调都会被拒绝。模型变更只看留出集是否显著变好；训练集和留出集的差距写入报告，但不作为门禁条件。

每次门禁会同时做多项检验，没有做多重比较校正。这在练手项目中可以接受，但报告中要写明：单次"显著"存在一定的误报概率。

发布就是把 active 指针切到新版本。回滚就是把指针切回 `parent_version`。在线服务每次判定前读取 active 版本（带短 TTL 缓存），切换不需要重启。模型版本的回滚就是切换 vLLM 中 adapter 的名称，基座模型不动。

留出集被门禁反复使用，本身也会被间接拟合。实验只跑 4 个周期，结束时把留出集的使用次数如实写进报告。

### 微调结论的判读规则

| 现象 | 结论 |
|---|---|
| v_b1 相对 v_a 没有显著提升 | SFT 不值得，只保留格式修复的价值 |
| v_b2 相对 v_b1 没有显著提升 | 外部数据在快手口径下无效，记录为"跨平台数据迁移失败"，主线沿用 v_b1 |
| v_b2 的误杀率显著高于 v_b1 | 外部标注口径和快手口径冲突，下调配比或去掉冲突来源 |
| 清洗后可用的外部样本少于 500 条 | 外部数据的投入不值得，阶段 3b 只保留流程记录 |
| v_c1 相对父版本显著提升，v_c2 没有 | 偏好数据的数量比来源更重要；反馈 DPO 的价值要等反馈量增长后才能体现 |
| v_c2 相对父版本没有显著提升 | 反馈数据太少，反馈 DPO 只算流程演示，报告中如实写明 |
| 微调后最好的版本仍不如 v0 | 如实报告差距。主线仍用开源模型，因为闭环需要可训练的模型；真实业务中应改用 API，并放弃权重通道 |
| v_a 的格式失败率超过 5% | 先做一轮只修格式的 SFT，再进入正式的 SFT 和 DPO |

### 已知局限

- 政策口径是快手的标签，不是自定义政策。微调在留出集上的提升，含义是"更贴近快手口径"，不代表模型能力普遍变强。
- 回放数据的分布和真实流量不同：真实流量里违规占比更低，误杀率在真实流量上会有不同表现。
- 模拟反馈的申诉率、举报率、恶意举报率是假设值，结论只说明机制有效，不代表真实用户行为。
- 留出集只有 300 条，只能检测较大的效果变化；小于置信区间宽度的改进会被判为"无显著变化"。
- KuaiMod 训练数据只有几百条，CoT 由教师模型生成，模型可能学到教师模型的表达习惯而不是判断依据。
- 外部数据的标签经过人工映射，"正常"样本还经过教师模型筛选，带有映射误差和银标噪声；训练数据混合了多个平台的标注口径。
- KuaiMod 自 2025 年起公开，基座模型或商用 API 的预训练数据中可能含有这些样本，无法排除数据污染。v0 和 v_a 的零样本结果因此可能偏高。
- 门禁中的多项检验没有做多重比较校正。
- 由 KuaiMod 训练出的权重受 CC-BY-NC-4.0 约束，不对外发布。

### 停止条件

出现以下任一情况，停止迭代并在报告中写明原因：

- 留出集指标连续 2 个周期都没有显著变化：当前各通道已调到头，剩余周期只做观察。
- 输出格式失败率超过 5%：先修输出约束，再谈策略。
- 人审占比超过 30%：阈值或模型区分度不够，自动处置没有意义。
- 7B–8B 模型在 128GB 显存上仍无法完成训练：说明训练配置有问题（如未开启 gradient checkpointing、图片 token 过多），先排查配置，不靠继续加显存解决。
