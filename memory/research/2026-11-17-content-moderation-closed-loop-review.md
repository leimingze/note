# 短视频 AI 审核闭环方案评审（2026-11-17）

## 结论

- 项目定位（用户明确）：练手项目，目标是证明理解 AI 审核全流程，不要求证明在自有业务流量上可靠。
- 在此定位下为 Go；以 KuaiMod test split（HF `KuaiMod/KuaiMod`，约 1k 条，CC-BY-NC-4.0，仅内部/非商用）作为人工锚点。
- 闭环对象是策略版本（提示词 + 阈值 + 判例集 + 模型快照），不做线上动态修改，按周期整版发布、离线回放验证、整版回滚。

## 数据切分决策

- 固定留出 300 条，只看总体指标，不看错例，不用于调参。
- 其余 700 条按周期轮换（约 100 条/周期），错例转成模拟反馈（误杀 → 申诉，漏判 → 按概率举报）。
- 按 tag 切分：2–3 个类别前几个周期不放入，第 4 周期起放入，模拟新违规类型，用来验证判例库通道。
- 每份 100 条时标准误约 3pp，所以单份数据不下结论，效果只在留出集上判断，并报告置信区间。

## 已否定的做法及原因

- 大模型模拟审核员/用户作为真值：优化目标会退化成"和模拟器一致"；模拟器只适合给归因管线做"注入已知答案"的测试。
- 开源平衡数据集估精确率/误杀率：正负例比例接近 1:1，远离真实流量（正例 1–3%），精确率会虚高。
- 不做：为对齐论文 92.4% 训模型、在线灰度（流量不足）、扩到 100 类。
- 2026-11-17 更新：用户可按需租用云 GPU（默认 64GB，不够可升 128GB；更大基座仅作为可选的独立变更），设计已加入微调通道：7B–8B 开源 VLM，用 ms-swift 做 LoRA。SFT 用第 1–3 周期数据（视为冷启动标注）；DPO 只用第 4–6 周期被反馈暴露并经人审确认的错例，负例取模型自己的错误输出。版本链为 v0 API → v_a 开源基座零样本 → v_b SFT → v_c DPO，每步都过门禁；推理用 vLLM 多 LoRA，回滚即切换 adapter。门禁新增规则：中间置信段 <2% 且错误率无显著下降时判为置信度失效。总工时变为约 27–29 人天。

## 失败/停止条件

- 留出集某主要类别正例 <30：该类不做单类结论（动手前先统计各 tag 条数）。
- 已用周期数据的提升超过留出集提升的 2 倍，或两者差距超过 5pp：判定过拟合，回滚。
- 留出集连续 3 个周期都在置信区间内波动：提示词/判例通道已到头。
- 用途变为商业产品：KuaiMod 数据不可用，方案作废。

## 产物

- 设计文档：`内容审核/AI审核闭环-设计.md`（STAR 结构）。审核服务对接 PulseFrame 已有契约（`POST /internal/review/tasks`、`/internal/review/callback`，结果只有 pass|reject）。中间置信段转人审，会超出发布审核 P95 ≤5 分钟的时效，文档中已注明。
- 写文档时 `实习项目/PulseFrame/docs/设计/业务模块设计/内容审核/` 在工作区处于已删除状态（未提交），新文档放在仓库根目录的 `内容审核/` 下。
- 执行方案：`内容审核/AI审核闭环-执行方案.md`。默认代码放在 PulseFrame `backend/`：新增 `internal/review` 模块和独立入口 `cmd/pulseframe-review`、`cmd/review-replay`；使用独立库 `pulseframe_review`；策略内容放 `backend/policies/vN/` 并入库；KuaiMod 数据放 `backend/data/kuaimod/`，不入库。里程碑为 M0 数据与基线 → M1 判定 → M2 判例、门禁、回滚 → M3 回放周期与验收 → M4 PulseFrame 集成，约 19 人天。代码位置尚待用户确认。

## 2026-11-17 审查后的修订（以设计文档为准，覆盖上文冲突内容）

- 数据切分改为：留出集 300 / 冷启动集 300（SFT、阈值标定、首批判例）/ 周期 4×100。延后类别不进入冷启动集和第 1 周期，从第 2 周期放入；合并后要求留出集正例 ≥30、第 3–4 周期 ≥30，否则场景 1 只做定性展示。
- 线上主线从一开始就是开源模型（v_a → v_b SFT → 周期 1–3 → v_c DPO → 周期 4 前瞻检查）；商用 API 只作 v0 参考和教师模型。原因：DPO 负例必须来自被训练模型自己的错误。
- 过拟合规则只用于提示词、阈值、判例变更，模型变更只看留出集显著性（否则 SFT 必被拒）。
- 采样从 3 次改为 5 次；模型变更时阈值按固定程序在冷启动集上重新标定，算作模型变更的一部分；判例只以文字注入；CoT 人工抽查 30 条，合格率 ≥80%。
- DPO 偏好对预计只有约 20–40 对，定位为流程演示。总工时约 28–32 人天，执行方案为 M0–M5。

## 2026-11-17 加入外部公开数据（用户提出 KuaiMod 训练数据不足）

- 外部数据只用于 SFT 和离线 DPO，不进入留出集（门禁只用 KuaiMod），也不进入反馈周期，原因是周期模拟的是同一平台、同一政策口径的流量。外部验证集按来源统计，仅用于诊断。
- 候选来源（许可均未核实，本会话无法访问 HF）：MultiHateClip、FakeSV（含快手视频，需重点和 KuaiMod 去重）、ToxiCN_MM、RWF-2000、XD-Violence；纯文本（COLD、ToxiCN）默认不用。爬取来源的色情类数据集禁止使用。
- 清洗流程：准入 → 统一形态 → 标签映射（来源中的"正常"不直接映射为 normal，先用教师模型筛查）→ 剔除延后类别 → 与 KuaiMod 去重 → 质量过滤 → 某来源 CoT 丢弃率 >30% 则整体丢弃 → 配比（外部 ≤ 冷启动集 3 倍，单一来源 ≤ 50%）→ 切成 SFT 池 / DPO 池 / 验证集。
- 版本链：v_a → v_b1（只用 KuaiMod 做 SFT）→ v_b2（混合 SFT，与 v_b1 比较）→ v_c1（外部 DPO 池离线 DPO）→ 周期 1–3 → v_c2（反馈 DPO）→ 周期 4。新增里程碑 M3b（7–10 人天），总工时约 34–41 人天；砍范围的优先级为 M0–M3 > M4 > M3b > M5。

## 2026-11-17 外部数据集联网核实（WebSearch 可用；WebFetch 访问 HF 和 arXiv 被拦截）

- CH-SV（ACM MM 2025，github.com/DLUTSSL/CH-SV）：6,728 条中文有害短视频，6 类（危险、冒犯、低俗、虚假、暴力、正常），无需申请：README 给出夸克网盘链接，原始视频、测试集、特征均已公开；许可 CC BY-NC-ND 4.0（不能分发修改后的数据）；README 要求研究或发表前先联系作者。定为外部数据主力。
- FakeSV：公开部分只有视频 ID 和标注，原始视频要通过 Google 表单签协议后获取；不按 ID 自行爬取。CH-SV 已有虚假类，FakeSV 降为有条件使用：KuaiMod 有虚假信息类标签且 CH-SV 虚假类不足时才申请；含快手视频，须去重。
- ToxiCN_MM：在 HF 填表申请，仅限研究，部分公开。HateMM：Zenodo 公开直接下载，作为保底。
- MultiHateClip：数据无明确许可，约 14% 视频失效，没有作者书面答复不用。Chinese-Toxic-Multimodal 片段约 2.3 秒，过短，不用。
- KuaiMod 有 17 个标签（multi-class），示例 tag 为 "pornographic"，二分类 judgement 为 是/否；完整标签名未查到，需 M0 从数据统计。
- 中文候选补充检索：真正能直接用的中文视频数据只有 CH-SV；ToxiCN_MM 为中文图片。NCSV 和 CTMD（MrHuangZy）在 GitHub API 中均无 license 字段，NCSV 只给视频 ID，不用。ChineseHarm-Bench（zjunlp，腾讯数据，CC BY-NC 4.0）只有文本，可作为文本侧参考或扰动测试素材，不用于 VLM 训练。HateMM 为 CC BY 4.0，1,083 条（Hate 431 / Non Hate 652），英文 BitChute 种族仇恨，建议作外部验证集或少量补充。

## 2026-11-17 基座模型最终选定（用户确认）

- 基座模型默认采用 **Qwen2.5-VL-3B-Instruct**（3B 多模态 VLM，可看视频帧）。
- 选择原因：Qwen3 系列最小的 VLM 只有 8B（Qwen3-VL-8B-Instruct），无法满足用户"更小参数、省显存"的诉求；Qwen2.5-VL-3B 是同时满足小参数与多模态的合适档位。
- 显存随之下调：默认租 24GB 显存实例，必要时升到 48/64GB；8B 及 30B 级更大基座仅作为可选的独立模型变更尝试。
- 设计文档与执行方案中"7B–8B 基座"与"默认 64GB/128GB 显存"表述已同步更新为 Qwen2.5-VL-3B 默认及对应显存。
- 服务器 `10.251.1.121` 上已存在 `Qwen2.5-VL-3B-Instruct`、`SmolVLM2-500M-Video-Instruct` 等候选模型目录；此前部署的 `Qwen3.6-27B-FP8`（`transformers serve`）因 transformers 4.57.6 不识别 `qwen3_5` 架构而无法推理，已关闭。
