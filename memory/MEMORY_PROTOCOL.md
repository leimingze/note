# 记忆管理协议

最后更新：2026-09-07

## 目的

本文档定义本项目中 agent 读取、创建和更新项目记忆的规则。

项目记忆用于保存未来工作需要继承的事实、决策、证据、推理过程、产物和交接信息，避免重要上下文只停留在聊天记录中。

## 核心原则

在任务授权范围内，将未来需要继承的重要事实和决策记录到 `memory/`，避免后续任务只能依赖聊天记录恢复上下文。

记忆默认使用中文。技术名词、命令、代码标识、路径、文档标题和外部链接可以保留英文。

`memory/` 只保存对未来工作有继承价值的信息，不保存临时闲聊、过程噪音或可从代码中直接推导的琐碎事实。

禁止在记忆文件中保存密钥、API Key、密码、私有 token、私钥或其他凭据。

## 优先级与冲突

用户当轮明确指令和已有授权优先于本协议及其他记忆文件；记忆本身不授予额外操作权限。

已明确的新长期要求或已验证的项目事实，在任务允许写回时更新相关记忆；用户的临时例外不自动转为长期约束。

如果无法判断是长期变化还是临时例外，继续执行当轮已授权工作，暂缓覆盖有歧义的长期条目。只有当前交付确实需要确定其长期效力时才询问用户；记忆维护的歧义不单独阻断业务任务。

## 记忆层级

长期记忆记录稳定事实和长期约束，写入：

- `memory/PROJECT_MEMORY.md`
- `memory/decisions/`

中期记忆记录阶段性方案、调研、计划和产物，写入：

- `memory/research/`
- `memory/artifacts/`

短期记忆记录重要会话、阶段性交接和临时上下文，写入：

- `memory/session-notes/`

当短期记忆被多次引用或开始影响后续工作时，应提升为中期或长期记忆。

## 按相关性读取

仅在任务依赖本项目持续上下文时使用以下流程；独立问题、无关子项目或当轮材料已充分的任务无需加载项目记忆。

1. 本协议在当前上下文中未加载或已发生变化时，读取本协议。
2. 需要项目当前事实时，读取 `memory/PROJECT_MEMORY.md`。
3. 根据当前问题选择相关会话记录、约束该任务的 ADR，以及已有调研或产物。先依据索引、文件名、日期和标题定位，再读取必要内容。

不要默认读取全部历史记录，也不要为常规任务扫描无关目录。当前上下文已有且未变化的内容无需重复读取；只有发现具体信息缺口时才扩大查找范围。

## 会话结束流程

当本次工作产生会影响未来的信息且任务允许修改文件时，更新对应记忆文件。用户要求只读、仅审查或不改文件时，不执行记忆写回。

需要记录的内容包括：

- 项目目标、范围、方向变化
- 架构、产品、数据、流程决策
- 工具、依赖、运行方式、部署方式变化
- 关键路径、数据位置、生成物位置
- 带来源的调研结论
- 后续不应重复的失败尝试
- 未解决问题、风险和交接信息
- 用户关于项目执行方式的长期偏好

如果只是很小的交流，且没有改变项目事实或任务状态，可以不新增记忆。

## 记录质量

重要记忆应尽量包含：

- 证据：来源、链接、命令输出、文件路径、版本号或用户明确指令。
- 思考：方案比较、取舍、风险、假设、重新评估条件。
- 结果：确认的事实、决策、更新文件、未解决问题或下一步动作。

不是每条记录都必须机械包含三个标题，但结论必须可追溯。

## 文件职责

### `memory/PROJECT_MEMORY.md`

保存项目当前稳定快照，保持简洁、准确、最新。

用于记录：

- 项目目标
- 已确认的用户需求
- 当前策略
- 当前已实现
- 当前资源与环境
- 架构方向
- 产品与体验方向
- 安全边界
- 记忆管理策略
- 开放问题
- 来源参考

### `memory/decisions/`

保存会约束后续工作的决策记录。

文件命名：

```text
ADR-0001-short-decision-name.md
```

建议结构：

```md
# ADR-0001：标题

日期：YYYY-MM-DD
状态：已采纳 / 已废弃 / 待验证

## 背景

## 决策

## 影响

## 替代方案

## 证据

## 后续约束
```

### `memory/session-notes/`

保存重要会话或阶段性交接记录。

文件命名：

```text
YYYY-MM-DD-short-topic.md
```

建议结构：

```md
# 会话记录：标题

日期：YYYY-MM-DD

## 背景

## 用户目标

## 相关上下文

## 证据

## 过程

## 结果

## 后续动作

## 需要同步到长期记忆的内容
```

### `memory/research/`

保存可复用调研、来源和取舍分析。

文件命名：

```text
YYYY-MM-DD-topic.md
```

建议结构：

```md
# 调研：主题

日期：YYYY-MM-DD

## 摘要

## 结论

## 来源

## 风险

## 建议
```

### `memory/artifacts/`

保存或登记重要独立产物，例如路线图、设计文档、实施计划、运维手册、验收清单。

如果产物本体较大，只记录索引和路径。

文件命名：

```text
YYYY-MM-DD-artifact-name.md
```

建议结构：

```md
# 产物：名称

日期：YYYY-MM-DD
类型：路线图 / 设计文档 / 实施计划 / 运维手册 / 验收清单 / 其他

## 路径

## 用途

## 状态

## 关联记忆

## 维护说明
```

## 更新纪律

更新记忆时：

- 默认使用中文记录核心信息。
- 保留可验证来源。
- 明确标记假设、风险和待验证事项。
- 不要为了显得确定而抹掉不确定性或失败尝试。
- 不要随意删除旧决策；如果决策变化，应更新或新增 ADR，并标记旧决策状态。
- 优先修改已有条目，避免重复堆叠。
- 过期内容可以标记为“已废弃”，并说明原因。

所有日期使用 `YYYY-MM-DD`。除 ADR 外，文件名使用小写英文、数字和连字符。

## 禁止记录

禁止写入：

- 密钥、API Key、密码、私有 token、私钥、凭据
- 临时闲聊或情绪性描述
- 无长期价值的过程细节
- 未标注的猜测
- 大段可从源码直接推导的实现细节
- 大型二进制内容本体
- 与项目无关的个人隐私信息

## 完成前检查

按会话结束流程判断本次是否产生需持续继承的信息；需要时只更新承担对应职责的文件。没有新信息或任务不允许写回时无需更新，也无需扫描各记忆目录来证明无需更新。
