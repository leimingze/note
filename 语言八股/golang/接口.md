# interface底层
eface和iface
```go
// runtime/runtime2.go（简化）
type eface struct {
    _type *_type          // 动态类型信息
    data  unsafe.Pointer  // 指向实际数据
}
例子：var i interface{} = 3
interface{} / any 没有方法，所以只需要知道：
现在装的是什么类型​ → _type
数据在哪里​ → data
内存上大概是：
eface {
    _type: &int 的元信息
    data:  -> 3
}
```

```go
type iface struct {
    tab  *itab           // 接口表：类型 + 方法表
    data unsafe.Pointer  // 指向实际数据
}

type itab struct {
    inter *interfacetype // 接口本身
    _type *_type         // 具体类型（运行时实际装进去的那个值的类型）
    hash  uint32         // 类型哈希，用于类型断言加速
    fun   [1]uintptr     // 方法表（实际是可变长数组）
}
```
# 底层发生了什么
```go
package main

import "fmt"

type Speaker interface {
    Speak()
}

type MyInt int

func (m MyInt) Speak() {
    fmt.Println("数字说话:", m)
}

func main() {
    var s Speaker = MyInt(42)
    s.Speak()
}
```
## 编译期：
1. 定义接口：
```go
type Speaker interface {
    Speak()
}
编译器生成 Speaker 的接口类型信息：
接口名：Speaker
方法数：1
方法签名：Speak() 接收者未知、无参数、无返回值
```
2. 定义类型+方法
```go
type MyInt int
func (m MyInt) Speak() { ... }
MyInt 底层是 int
MyInt 的方法集里有 Speak()
Speak 的接收者类型是 MyInt（值接收者）
```

## 运行时
1. 创建数据
2. 查找/创建itab
```go
itab {
    inter:  &Speaker 的类型信息
    _type:  &MyInt 的类型信息
    hash:   MyInt 类型 hash
    fun:    [MyInt.Speak 的函数地址]
}
```
3. 组装iface
```go
s (Speaker)
┌──────────────────────────────────┐
│ iface                            │
│                                  │
│  tab  ────────────────┐          │
│  data ─────────────┐  │          │
└────────────────────┼──┼──────────┘
                    ↓  ↓
                   itab
        ┌────────────────────────┐
        │ inter → Speaker       │
        │ _type → MyInt         │
        │ hash  → 0x7a3b...     │
        │ fun[0] → MyInt.Speak  │
        └────────────────────────┘
                    │
                    │ data 指向
                    ↓
                  ┌────┐
                  │ 42 │  ← MyInt 值（堆上）
                  └────┘
```
4. 运行到s.Speak()时
```go
s.Speak()
1. 读 s.tab → 拿到 itab 地址
2. 读 itab.fun[0] → 拿到 MyInt.Speak 的函数地址
3. 读 s.data → 拿到 42 的地址
4. 调用 MyInt.Speak(42)
```

# iface和eface区别是什么
iface和eface的核心区别在于是否包含方法信息。

eface是空接口interface{}的底层实现，结构非常简单，只有两个字段：_type 指向类型信息，data 指向实际数据。因为空接口没有方法约束，所以不需要存储方法相关信息。

iface是非空接口的底层实现，结构相对复杂，包含 itab 和 data。关键是这个 itab，它不仅包含类型信息，还包含了一个方法表，存储着该类型实现的所有接口方法的函数指针。

# interface可以比较吗
可以比较
接口比较 = 先比 itab的*_type（类型），类型相同再比 data（值）
```go
type itab struct {
    inter *interfacetype // 接口类型（用于断言："你实现了我吗"）
    _type *_type         // 具体类型（比较时用这个）
    hash  uint32         // 类型哈希（加速类型断言）
    fun   [1]uintptr     // 方法地址表（调用时用，比较不用）
}
```
