# 传输层：脱稿记忆

[返回总览](传输层.md) · [覆盖检查](传输层-覆盖检查.md)

- **课堂数据怎样传送？** 选协议、建连接、传数据、关连接、查故障。
  - **A｜怎样选择协议？** 先看交付、时延、消息边界与控制需求。
    - **A02 TCP：** 用连接状态管理一条可靠、有序的字节流。
      - **A03 两个端点：** 每条连接管理一对端点，服务器可以管理多条连接。
      - **A04 可靠性：** 编号与确认记录进度，校验与重传应对传输问题。
        - **A05 交付边界：** send 进入本机缓冲区，ACK 确认对端接收，业务确认保存完成。
      - **A06 字节流：** 字节有顺序，应用消息没有天然边界。
        - **A07 定界：** 固定长度、长度前缀、分隔符，由应用协议定义消息。
      - **A08 TCP 首部：** 端口、编号、确认、标志与窗口表达通信状态。
        - **A09 SEQ、ACK：** 数据按字节推进，SYN、FIN 各占一位，ACK 指向下一个期望字节。
        - **A10 控制位：** ACK 确认，SYN 同步，FIN 结束一个方向，RST 重置。
        - **A11 首部长度：** TCP 有选项，长度通常 20～60 字节；UDP 固定 8 字节。
      - **A12 应用：** FTP、HTTP/1.1、HTTP/2 常用 TCP；HTTP/3 使用 QUIC。
      - **A13 局限：** 有序交付会等待缺口，连接建立、状态维护、迁移和加密各有成本或条件。
    - **A14 UDP：** 直接发送有边界的数据报，交付与控制策略由上层补充。
      - **A15 首部：** 端口负责分发，长度描述数据报，校验检查损坏。
      - **A16 应用：** 传统 DNS、音视频、广播或组播，注意协议版本条件。
        - **A17 丢包：** 依据消息期限和完整性要求决定恢复方式。
          - **A18 可靠 UDP：** 补齐编号、确认、恢复、顺序与控制，QUIC 提供已有方案。
    - **A19 对比：** 连接、对象、可靠性、控制、首部、边界、大消息。
      - **A20 MSS、MTU：** TCP 数据按 MSS 等条件分段，IP 包受路径 MTU 约束。
      - **A21 长度：** UDP 自带数据报总长度，TCP 利用 IP 提供的承载长度。
      - **A22 同号端口：** TCP 和 UDP 各自管理端口，TCP 443 与 UDP 443 可以共存。
  - **B｜怎样建立连接？** 标识端点、同步序号、接纳连接。
    - **B02 socket：** 应用访问网络的接口及其状态对象。
      - **B03 四元组：** 源 IP、源端口、目的 IP、目的端口确定连接两端。
    - **B04 三次握手：** SYN、SYN+ACK、ACK，同步双方 ISN 并完成确认。
      - **B05 第一次：** SEQ=x，客户端进入 SYN-SENT。
        - **B06 丢失：** 客户端超时重传同一 ISN 的 SYN。
      - **B07 第二次：** SEQ=y、ACK=x+1，服务端进入 SYN-RECEIVED。
        - **B08 丢失：** 两端按各自定时器重传 SYN 或 SYN+ACK。
      - **B09 第三次：** SEQ=x+1、ACK=y+1，服务端收到有效确认才进入 ESTABLISHED。
        - **B10 丢失：** 重传 SYN+ACK 触发再次确认，后续有效数据也可能完成握手。
      - **B11 三次原因：** 双方 ISN 都需要得到对方确认。
      - **B12 ISN 变化：** 区分连接序号空间，并降低预测序号的风险。
      - **B13 TLS：** 普通路径接续 TCP；TFO 可重叠部分报文，TLS 0-RTT 不省略 TCP 握手。
    - **B14 接纳连接：** listen 接收请求，两类队列管理握手前后的等待。
      - **B15 半连接：** 等待第三次握手，SYN cookies 可改变状态保存方式。
        - **B16 SYN 丢弃：** 检查报文、过滤、资源与队列策略，超时不能直接证明队列满。
      - **B17 全连接：** 已完成握手，等待应用 accept。
        - **B18 未 accept：** 内核仍可完成握手，条件是队列和资源允许。
      - **B19 未 listen：** 可达且没有匹配 socket 时通常返回 RST，过滤可能表现为超时。
    - **B20 异常 SYN：** 已有连接按状态验证，支持 RFC 5961 的路径使用 challenge ACK。
  - **D｜怎样可靠传送？** 记进度、补缺口、连续发送、控制发送量。
    - **D02 未确认：** 数据或 ACK 都可能丢失，保留数据等待补发。
      - **D03 超时重传：** 到期补发，连续超时增大 RTO。
        - **D04 RTO：** 根据平滑 RTT、波动和系统限制确定。
      - **D05 快速重传：** 经典算法看到三个重复 ACK，提前重传疑似缺失段。
        - **D06 示例：** 101～200 补齐后，缓存的 201～500 连续，ACK 从 101 跳到 501。
    - **D07 滑动窗口：** 允许连续发送，确认前进后释放额度。
      - **D08 累计确认：** 有效 ACK 700 覆盖 ACK 600，不代表编号 700 已收到。
      - **D09 可发额度：** 约为 min(cwnd, rwnd) 减去在途量，并满足窗口边界。
    - **D10 流量控制：** rwnd 表达接收能力，保护接收缓存。
      - **D11 零窗口：** 暂停常规新数据，保留控制报文与探测。
        - **D12 持续计时器：** 探测当前窗口，恢复丢失的窗口更新信息。
    - **D13 拥塞控制：** cwnd 根据网络反馈变化，保护链路。
      - **D14 慢启动：** 理想情况下每 RTT 约翻倍，初始窗口依标准和系统而定。
      - **D15 拥塞避免：** 经典 Reno 每 RTT 约增加一个 SMSS。
      - **D16 信号：** 超时、重复 ACK、ECN 提供控制依据，不能单凭它们断定根因。
        - **D17 超时响应：** Reno 阈值按在途量减半且至少 2 SMSS，cwnd 回到 1 SMSS。
        - **D18 快速恢复：** 阈值减小，窗口临时增加 3 SMSS，收到新 ACK 后回到阈值。
  - **C｜怎样结束连接？** 两个方向各自结束，FIN 要按序确认。
    - **C02 四次原因：** 确认对端结束与结束自身发送可能发生在不同时刻。
      - **C03 合并三次：** ACK 与 FIN 时机重合时可以合并。
    - **C04 第一次：** 客户端发 FIN，进入 FIN-WAIT-1，仍可接收。
      - **C05 丢失：** FIN 超时重传，持续失败按系统规则结束。
    - **C06 第二次：** 服务端进入 CLOSE-WAIT；客户端收到确认后进入 FIN-WAIT-2。
      - **C07 丢失：** 客户端重传 FIN，服务端再次确认。
    - **C08 第三次：** 服务端发 FIN，进入 LAST-ACK。
      - **C09 丢失：** 服务端重传，客户端 FIN-WAIT-2 的期限受系统与持有状态影响。
    - **C10 第四次：** 客户端发 ACK 后进入 TIME-WAIT，服务端收到后进入 CLOSED。
      - **C11 丢失：** 重传 FIN 触发再次 ACK，并重新开始等待计时。
    - **C12 乱序 FIN：** 前面的字节未连续收到，就不能越过缺口交付结束标志。
    - **C13 TIME-WAIT：** 保留关闭后的通信状态，协议模型等待 2MSL。
      - **C14 必要性：** 回应重复 FIN，隔离新旧连接。
      - **C15 资源：** 占内核状态，约束连接组合，不等同整个本地端口不可用。
      - **C16 服务端很多：** 检查短连接、长连接空闲超时与请求数上限导致的主动关闭。
      - **C17 新 SYN：** 接纳条件依赖内核、监听、序号与时间戳。
      - **C18 tcp_tw_reuse：** 复用必须满足条件，默认值与适用范围需要结合 Linux 版本。
  - **E｜故障怎样发现？** 根据报文或计时证据判断连接状态。
    - **E02 断电：** 本端状态消失，对端依靠后续通信、超时或探测发现。
    - **E03 进程退出：** 内核仍能清理 socket，FIN、RST 或继续持有取决于当前状态。
    - **E04 拔网线：** 状态未超时且网络条件恢复时可能继续，不能保证自动延续。
    - **E05 两种保活：** TCP Keepalive 探测连接，HTTP Keep-Alive 复用连接。
      - **E06 应用检测：** 业务超时和心跳确认应用响应，TCP 可达不证明业务可服务。
